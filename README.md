# Mirror Abyss 4.0.122


## 4.0.122

- 历史 Edit / Swipe / Delete 的自动提取补建不再从变更点一路重放到聊天尾部；直接读取 SillyTavern 当前 `world_info_depth` 作为有限补建边界。ST release 默认 `world_info_depth = 2`，玩家修改 ST Scan Depth 后镜渊自动跟随，不新增镜渊自己的范围设置。
- 这里复用的是 ST 已有的 World Info 扫描范围参数，不宣称 ST 原生定义了“历史恢复必须补 N 条”；镜渊只是拒绝再发明第二个历史范围。宿主值不可读时保守回退到 ST release 默认值 2。
- Delete 先用删除前后身份快照确定真实删除位置，再把旧 receipt 索引映射到删除后的聊天坐标后计算补建窗口，避免把 ST 的 `MESSAGE_DELETED = post-delete chat.length` 当删除消息 ID。
- 有限窗口只回滚并重建窗口内 receipt；窗口外较新 receipt 继续保留。若窗口外 receipt 曾更新同一 UID，镜渊在回滚前冻结这些较新 UID 的当前权威状态，并在窗口补建结束后恢复，避免“少重放”反而机械抹掉后续已接受状态。
- 历史恢复链内不再调用只负责入队的 `自动处理()` 假装等待；改为按范围直接串行执行 `extract`，一条真正完成后再进入下一条。普通新回复的自动处理队列保持不变。
- 不重新执行历史终稿处理，不新增 Scene dependency graph、UID 无限传播、Job Queue 或固定 `N` 楼设置；超出 ST 当前扫描范围的极端跨轮语义依赖明确裁掉。
- 新增回归：ST depth=2 只有限补建、depth=4 自动扩大同一窗口、范围外 receipt 保持存在、范围外较新 UID 状态不会因窗口内回滚被擦除。


## 4.0.121

- 给“辅助提取请求”增加独立硬上限 `16000 tokens`；这个上限只约束 Mirror Abyss 自己发送给提取模型的输入，不读取、不修改 SillyTavern 的 `world_info_budget` / `world_info_budget_cap`。
- 输入预算按宿主 token counter 计算：优先使用 `getTokenCountAsync` / `getTokenCount`；只有宿主没有计数能力时才使用保守字符估算。
- 超限时不启动第二批模型请求，也不增加 Top-K/向量/冲突合并：先压薄身份目录别名，再在极端规模下按原生 `order` 保留更高优先身份；随后按 ST 本轮 `WORLD_INFO_ACTIVATED` 的既有顺序逐条装入完整召回详情，预算装满即停。
- 玩家本轮输入和当前最终 AI 正文不允许被截断；如果仅这部分固定输入就已经无法装入 16k，上游提取直接以 `EXTRACTION_INPUT_TOO_LARGE` 失败关闭，不发送半截事实。
- 详细召回被裁切时，未展开对象仍尽量保留 UID / 类型 / 稳定名称身份，不把“没展开正文”误当成“对象不存在”。
- 新增回归：大规模 `WORLD_INFO_ACTIVATED` 时整次提取输入不得超过 16k、不得因裁切变成多批多次模型调用、身份目录优先保留；当前正文自身超限时零模型调用并零写入。
- 历史 Edit / Swipe / Delete 的 Scene-range 补建本版**没有强行修改**：旧 receipt 没有可靠的逐消息 scene range，直接按场景截断会破坏后续同 UID 更新链。该项继续保持 4.0.120 行为，等来源范围可证明后再改。


## 4.0.120

- 将“审核”收敛为单一“终稿处理”阶段：玩家仍只维护一份可编辑要求，这份要求既可以用于审核，也可以用于纠错、去 AI 腔、润色或风格约束。代码不理解玩家规则语义。
- 终稿正常路径固定为一次模型调用：无需修改时只接受精确 `[通过]`；需要修改时同一次请求直接返回完整最终正文并以 `[修正完毕]` 收口。只有返回协议损坏、截断或附加多余内容时允许同一任务唯一一次协议纠错；取消“独立二审 → 修正 → 修正后复核”的 2–4 次常态链。
- 终稿处理继续冻结 chat/message/swipe/text 身份，修正文只有通过 ST 后端聊天回读核验后才视为成功；减的是重复模型工作，不减宿主写回安全。
- 提取参考改为两层：全书只发送镜渊 managed 条目的薄身份目录（UID/类型/稳定名称/少量别名），详细旧正文只展开 SillyTavern 本轮 `WORLD_INFO_ACTIVATED` 实际召回且属于当前镜渊世界书的条目。辅助终稿/提取请求本身不重新执行 ST World Info 扫描。
- 不新增 Top-K、Embedding、向量数据库或第二召回器；谁被召回、递归、预算裁剪继续由 SillyTavern 原生 World Info 负责。镜渊保留既有 `position/order` 类型区间。
- 不修改玩家的 `world_info_budget` / `world_info_budget_cap`。ST release 默认 World Info Budget 为 25%；社区插件预算只作为参考，不把旧版 50% 配置重新固化进镜渊。
- `存()` 不再把全局 `重排()` 作为所有世界书保存的隐式副作用。自动提取、导入、总结、整本整理这类叙事/结构写入仍显式重排；普通手动正文、召回关键词、常驻、基石、定义位置、文件夹、焦点、Undo/恢复只保存目标变化。
- Edit / Swipe / Delete 的历史补建不再重新执行终稿处理；当前版本仍保留提取补建，受影响范围闭包/Scene-range 粒度留待专项实测后再改，避免本版同时改动尚未闭合的恢复语义。
- 小总结/大总结触发与“总结完成后再放行”时序保持 4.0.119，不引入后台 maintenance、抢占或通用 Job Queue。
- 宿主合同回归新增：终稿单次通过、单次直接修正、协议纠错最多一次、完整链调用预算、ST 实际召回详情裁剪、未召回条目正文不进入提取请求、普通手动保存不全局重排。


## 4.0.119

- 取消链补齐 SillyTavern 真实宿主终止：Connection Profile 继续使用独立 `AbortSignal`；跟随当前 ST 连接时，镜渊任务被取消会调用宿主 `stopGeneration()`，让 `generateRaw` 内部监听的 `GENERATION_STOPPED` 真正中止底层请求。宿主原生 Stop 事件也会取消正在运行的镜渊任务。
- “整理整本世界书”改为非破坏性全书批处理：先读取整本紧凑索引，再按完整正文分批逐条整理；每批必须回传全部输入 E 编号并以 `[整理完毕]` 收口，漏返/截断直接失败且零写入。整本整理不再把未返回 E 解释为删除，也不再自动合并或新增条目。
- 整本整理预览只在内存形成候选；提交前重新 fresh-read 世界书并比较整本指纹，玩家在预览后做过任何修改时拒绝陈旧覆盖。非镜渊条目可以被逐条整理正文，但不会被接管为 `managed`；基石保持不动。
- 审核改为“初审 → 独立复核 → 必要修正 → 修正后复核”。首次 `[通过]` 不能单独成为最终通过；第二审核者必须从零重新按玩家规则找反例。发现问题后先生成候选修正文，只有修正后再次完整审核精确 `[通过]` 才允许覆盖正文。
- 审核语义仍完全来自玩家填写规则：没有增加硬编码剧情规则、正则语义判断、角色卡/世界书隐式审核依据或默认焦点规则。
- 新增宿主合同反例回归：当前连接底层真取消、宿主 Stop 取消 Profile、第一次误通过被复核抓住、修正复核失败保留原文、整本多批全覆盖、漏 E 零写入、预览后玩家修改拒绝覆盖。


## 4.0.118

- 以 SillyTavern release 实际宿主合同收口异步主链：自动处理只在 `MESSAGE_RECEIVED + CHARACTER_MESSAGE_RENDERED` 同一消息握手完成后进入队列，不再使用 `GENERATION_ENDED` 作为正文完成信号。
- 异步任务冻结当前 `chatId + message index + swipe_id + send_date + 正文指纹`；切聊、Edit、Swipe、Delete 会取消受影响任务，陈旧结果不得继续审核、提取或写入。
- `MESSAGE_DELETED` 不再把事件参数当消息 ID；改用删除前后消息身份快照机械定位删除起点与数量，再回滚并重排 receipt。
- Connection Profile 请求使用正式 CMRS `AbortSignal`，并恢复 Profile 的 preset/instruct；Chat Completion 与 Text Completion 均走宿主正式 Profile 合同。
- 世界书写入改为 `saveWorldInfo → 后端 no-cache fresh read → 提交指纹核验`；回读内容不等于预期提交时直接失败，不显示完成。
- 审核修正文写入后通过 ST `/api/chats/get` 或 `/api/chats/group/get` 做后端回读核验；`saveChatConditional()` 静默失败或超时时不得显示完成，也不得继续提取。
- 合并 4.0.116/4.0.117 已确认审核行为：最近完整对话只辅助指代；玩家审核要求位于实际用户请求；通过必须精确为 `[通过]`；不通过一次返回完整修正文并以 `[修正完毕]` 收口。
- 运行页保留自动修正，同时增加“查看当次审核原文”按钮；未知、未运行、跳过状态不会显示成“已通过”。

- 界面继续把“手动常驻”和“焦点强制常驻”分开显示，避免焦点人物的手动开关产生误导。

## 4.0.105

- 审核与修正重新分离：审核固定只返回 `[通过]` 或 `[不通过] + 问题`；只有明确不通过才发起第二次修正请求，审核协议错误绝不替换正文。
- 审核输入加入本轮玩家输入，使角色边界审核能够识别玩家已明确给出的意图、方向、要求与授权。
- 场景切换顺序改为：先完成本轮提取并解析出新场景，但暂不写入；立即用“本轮写入前”的旧 SceneGroup 小总结；达到水位立即大总结；随后 fresh read，再写入本轮新场景事实。
- 本轮提取事实不再污染刚结束场景的小总结输入；小总结与大总结产生的变化仍与触发它们的玩家回合一起记录，可统一回滚。
- 消息 Edit / Swipe / Delete 不再 `cancel++ + autoQueue=[]` 清空全部待处理正文；只移除受影响区间，排在前面的无关正文继续处理。
- 正在处理的受影响正文会立即失效；若取消发生在回执写入前，使用本回合进入提取前的世界书/SceneGroup 临时快照恢复；已完成回合继续用 receipt 前像一次恢复并重跑后续现存正文。
- 修复取消后 `busy` 可能永久不释放的问题；任务 finally 始终释放自身 busy。
