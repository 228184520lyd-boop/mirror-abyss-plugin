# Mirror Abyss｜镜渊

SillyTavern 正文审核与世界书维护插件。

版本：`2.0.0-core.realtest.7`

## 定位

Mirror Abyss 只完成这条链路：

```text
AI 正文
→ 审核
→ 必要时一次修正
→ 事实提取
→ 文本解析
→ 确定性匹配
→ 世界书增删补替
```

- SillyTavern 负责正文生成和世界书原生召回；
- 世界书是唯一长期剧情数据源；
- 模型负责语言理解与总结；
- 插件负责解析、匹配、UID、增删补替和写入校验；
- UI 只读取和映射当前世界书，不保存第二份剧情数据。

插件不建立人物数据库、事件数据库、事实账本、自建向量库、自建递归引擎、自建召回系统、Agent 或剧情状态机。

## 模型任务

### 审核

只允许返回：

```text
PASS
```

或者：

```text
FAIL

原因:
1. ……
2. ……
```

审核只检查玩家控制、知识限制、世界规则和人物一致性，不评价文风或剧情质量。

### 修正

只有审核失败时调用一次。模型只返回修正后的完整正文，不输出分析、原因或修改记录。

### 事实提取

```text
类型｜稳定名称

【信息类别】

一条明确事实
```

模型不得输出 UID、世界书操作、删除命令、常驻、向量、递归、深度或顺序。没有值得保存的信息时只输出 `无`。

### 小总结

```text
总结｜当前事件

【当前情况】
……

【关键状态】
……

【未解决事项】
……
```

保留下一阶段继续当前剧情必须知道的信息。每次新结果整段替换同名旧条目。

### 大总结

```text
总结｜世界历史

【长期变化】
……

【重要事件】
……

【长期关系】
……
```

只保留跨场景仍成立的长期影响。每次新结果整段替换同名旧条目。

小总结和大总结都只返回一个总结条目，不返回人物块、UID、分发目标、退出建议、删除、归档或其他操作命令。

## UID

模型不生成、看不到、也不返回 UID。

世界书标题始终保持：

```text
类型｜名称
```

插件使用 SillyTavern 世界书原生 `uid` 作为唯一提交身份，并把身份标记写入关键词：

```text
名称
其他别名或触发词
UID:原生uid
```

标题编辑、关键词编辑、焦点切换、锁定和自动写入都会保留 `UID:原生uid` 关键词。UID 关键词不会提供给模型，也不会参与普通关键词召回匹配。

## 匹配评分

代码按以下等级建立候选：

| 匹配依据 | 分数 | 行为 |
|---|---:|---|
| 原生 UID | 100 | 唯一命中时直接匹配 |
| 完整标题 | 95 | 唯一命中时直接匹配 |
| 标准化标题 | 90 | 唯一命中时直接匹配 |
| 类型＋名称 | 80 | 唯一命中时直接匹配 |
| 同类型别名 | 70 | 只作辅助，不自动覆盖 |
| 同类型关键词 | 50 | 只作辅助，不自动覆盖 |
| 正文内容 | 30 | 只作辅助，不自动覆盖 |

只有唯一最高候选达到 80 分才自动写入。50–79 分只显示人工确认信息，不覆盖旧条目；低于 50 分时才创建新条目。

## 增删补替

- `create`：没有可信目标时创建新条目；
- `append`：补充固定事实、经历、事件进程、关键词和关联；
- `replace`：替换同一状态槽或明确要求整段替换的栏目；
- `delete`：只由插件执行，模型没有删除权限；
- `no-op`：完全重复、标准化重复、空内容、低分辅助候选或越界内容不写入。

状态槽优先使用：

```text
字段：当前值
```

例如：

```text
当前位置：城堡。
身体状态：左臂受伤。
事件状态：进行中。
```

同一字段只保留最新当前值。固定事实、经历和事件进程先去重，再追加。

重复判断顺序：完全相同 → 标准化相同 → 小模型返回 `SAME` 或 `DIFFERENT`。否定、失去、不再、身份改变、关系改变、位置改变、数值升降和状态变化必须视为不同事实。

## NPC 退出

不建立生命周期状态机。

插件只能清理提取时明确使用 `NPC｜名称`、并由插件加上 `临时` 管理关键词的一次性 NPC 条目，并且必须同时满足：

- 不是玩家焦点；
- 不是基础设定；
- 没有用户锁定；
- 总结没有继续承接该角色；
- 没有关系、任务、契约、能力、历史事实或其他长期绑定；
- 没有仍被其他条目引用。

总结模型只生成总结文本，不输出删除命令。普通人物和重要 NPC 不会因为总结没有提及就自动删除。

## SillyTavern 原生字段

插件不实现召回，只映射规格明确授权的字段：

| 条目 | `constant` | `vectorized` |
|---|---:|---:|
| 基础设定 | `true` | `false` |
| 玩家手动焦点 | `true` | 按原条目类型保留 |
| 普通人物、事件、地点、物品、组织、总结等 | `false` | `true` |

关键词触发写入 ST 原生 `key`，包括名称、别名、用户触发词和 UID 身份关键词。

插件**不修改**用户在 SillyTavern 中设置的：

- `preventRecursion`
- `excludeRecursion`
- `delayUntilRecursion`
- `depth`
- `order`
- `position`
- `role`
- `selective`
- `probability`
- sticky、cooldown、delay、分组等字段

新建条目采用 SillyTavern 自身的新条目默认值；之后由用户在 ST 中调整递归、深度、顺序和位置。玩家焦点只切换 `constant`，不改其他召回参数。

## UI

UI 是当前世界书的查看和编辑映射：

- 打开时读取世界书；
- 显示条目、关键词、栏目和内容；
- 编辑时通过唯一世界书写入器保存；
- 保存后重新读取世界书；
- 关闭或切换聊天时清空临时映射；
- 不保存剧情，不判断事实，不成为第二数据源。

## 安全边界

- 插件启动、UI 打开和聊天切换不会自动调用模型；
- 模型返回和世界书提交前校验聊天、消息、正文哈希和目标世界书；
- 每个聊天同时只运行一个核心处理流程；
- API、解析或保存失败时停止本轮，不进行部分写入；
- 世界书保存后回读验证；
- 聊天切换后丢弃旧任务结果；
- 完整处理过的同一消息直接跳过。

## 安装

安装包根目录包含：

- `index.js`
- `app.js`
- `manifest.json`
- `README.md`
- `LICENSE`

在 SillyTavern 中安装 ZIP，打开镜渊设置，选择当前聊天世界书和各模型任务使用的 Connection Profile。Profile 留空时使用当前连接。

## 实机检查

1. 安装启用后确认没有启动模型请求；
2. 打开工作区，确认 UI 只读取当前聊天绑定世界书；
3. 生成新事实，确认标题为 `类型｜名称`，关键词中包含 `UID:原生uid`；
4. 确认模型输出中没有 UID；
5. 确认审核使用 `PASS/FAIL`；
6. 确认小总结只有 `总结｜当前事件`；
7. 确认大总结只有 `总结｜世界历史`；
8. 确认基础设定为常驻且关闭向量，普通条目开启向量；
9. 修改某条目的递归、深度、顺序或位置，再由插件更新正文，确认这些字段保持不变；
10. 切换玩家焦点，确认只改变 `constant`；
11. 在模型返回前切换聊天，确认旧结果不能写入新聊天。
