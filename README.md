# Mirror Abyss 2.0.0-lite.ui.64-source-title-identity

Mirror Abyss（镜渊）是 SillyTavern 前端扩展，用于在 AI 正文完成后执行可选审核、完整修正、事实提取、分层总结、世界书提交和原生召回配置。

本版本的工程边界固定为：

- 世界书是唯一长期剧情数据源。
- 插件只负责读取、转换、校验和提交，不建立第二剧情数据库。
- 模型只产生候选协议；匹配、合并、原生字段设置、提交与回滚由插件确定性执行。
- 当前聊天绑定的世界书是唯一写入目标；全局旧字段不能覆盖聊天绑定。
- 所有模型路由和世界书保存均通过 SillyTavern 官方接口。

## ui.64 来源标题身份修复

- 总结提示词集中列出必须逐字复制的来源标题。
- 同标题关联条目不再覆盖唯一 pending 来源。
- 常见连接符与空格差异只在候选唯一时映射回权威来源。
- 多个 pending 来源身份冲突时拒绝猜测并保留回滚。

## 安装

将最终候选 ZIP 作为 SillyTavern 第三方扩展安装。最低客户端版本为 SillyTavern 1.18.0。

安装后，页面右侧会显示镜渊浮动入口。插件面板分为：

- **运行**：完整处理、单独审核、单独提取、取消任务和阶段状态。
- **世界书**：整理世界书主入口、折叠式高级手动总结、世界书状态和召回状态。
- **设置**：功能开关、阶段 Profile、API 探针、预算、提示词和栏目定义。
- **维护**：设定导入、世界书重建、重置、自动验收和诊断导出。

## 官方宿主接口

2.0.0-lite.ui.64-source-title-identity 只使用 SillyTavern 当前公开宿主字段：

- 生命周期和消息：`eventSource`、`eventTypes`、`MESSAGE_RECEIVED`、`GENERATION_ENDED`。
- 主连接原始生成：`generateRawData`，旧宿主回退到 `generateRaw`；当前连接不传 `responseLength`，避免修改主正文全局输出长度。
- 独立模型路由：Chat Completion Profile 优先使用 SillyTavern 官方 `ChatCompletionService.processRequest`，显式传入 Profile 的 `secret-id`、模型和自定义 URL；其他 Profile 回退 `ConnectionManagerRequestService.sendRequest`。两条路径都不读取原始 API Key。
- 世界书：`loadWorldInfo`、`saveWorldInfo`、`updateWorldInfoList`、`reloadWorldInfoEditor`。
- 聊天和元数据：`saveChat`、`saveMetadata`、`chatMetadata`。
- STscript：`executeSlashCommandsWithOptions`。

插件不会直接请求模型供应商端点，不会拼接 `/v1` 或 `/chat/completions`，也不会保存、显示或读取原始 API Key。

## 处理链

正常完整处理顺序：

1. 固定当前聊天、正文、消息键、内容哈希、角色和世界书快照。
2. 审核正文。
3. 审核失败时生成完整修正版；截断、缺段、异常缩短或结尾不完整的修正版禁止覆盖。
4. 提取使用自然中文条目协议，并兼容旧 `ENTRY` 协议；格式异常时只允许一次修复，连续仅推理时进入最终协议救援或分段提取。
5. 插件生成确定性操作计划并提交世界书。
6. 保存提交回执和当前游戏时间。
7. 按阈值执行小总结、大总结和沉降分发。
8. 最后保存处理游标并刷新四阶段状态。

任何后段失败都会按逆序恢复本回合已提交的世界书、回执、游戏时间和元数据。源正文被编辑、删除或切换时，近期提交按回执幂等回滚并重新排队。

## 请求稳定性

- Profile 请求支持真实 `AbortSignal`；取消或超时会中止浏览器网络请求。
- `Failed to fetch`、`Load failed`、连接重置、502、503、504、HTML 错误页等按类型执行有限退避重试。
- 400、协议错误、用户取消不会被错误重放。
- 没有单独紧凑提示词的阶段会复用原请求重试，不再直接失败。
- 请求连续失败时保留真实最终错误和尝试次数。

## 世界书事务

- 只有官方 `saveWorldInfo` 一个写入器。
- 保存后使用后端权威读取验证；网络读取失败不得退回缓存冒充成功。
- 条目编辑、焦点、锁定、召回重排、提取、总结和重建都执行保存—权威回读—验证。
- 验证失败时恢复旧世界书并再次权威回读。
- 重建同时修改世界书和关键词定义；提交与撤销均为双资源事务。
- 世界书恢复成功后才允许清理提交回执；恢复失败时保留回执以便后续重试。

## 自动验收

自动验收会在真实 SillyTavern 宿主中保存聊天、元数据、世界书和连接状态快照，然后运行三轮相互隔离的全量检查。

每轮从原快照重新开始，覆盖：

- 官方连接与端点完整性。
- Profile 实机调用和审核/提取协议。
- 世界书写入、权威回读和回滚。
- 主聊天 `/send`、`/trigger` 和正式生成生命周期观测。
- 插件确定性完整闭环、修正分支、幂等性和世界书原生召回配置。
- 网关、HTML、空正文、仅推理和协议错误分类。
- 聊天、元数据、世界书和主生成状态恢复。

稳定候选要求插件闭环三轮全部通过；不会再用一轮成功覆盖其他失败轮次。主聊天外部连接结果单独报告。

## 数据安全

- 诊断导出会隐藏 secret、密码、API Key、授权字段和连接 URL，只保留哈希指纹。
- 自动验收的临时聊天消息和世界书条目结束后必须恢复。
- 聊天切换后，旧任务禁止向新聊天执行保存或反向保存。
- 插件重置不删除世界书；设置重置和当前聊天状态重置组成跨资源事务。

## 本地验证范围

本地矩阵验证插件可控的有限状态、故障注入和宿主模拟，不等同于对所有第三方模型和网关的永久可用性保证。真实环境结果以插件导出的自动验收报告为准。

- 补齐结果格式不合格时仍只允许一次纯格式修复；补齐后重新合并并校验全部原 pending 来源。
- 错误信息会列出具体遗漏来源标题，便于实机定位模型遗漏还是内部工作集缺失。
- ui.62 的固定格式、语义防补写、最小总结间隔，以及 ui.61 的确定性结算与无裁剪 pending 全部保留。

详细实现见 `PATCH-SCOPE-UI63.md`、`UI63-MISSING-SOURCE-COMPLETION-VALIDATION.md` 与 `UI63-REALTEST-CHECKLIST.md`。

## 2.0.0-lite.ui.62-fixed-summary-contract 本轮改动

- 小总结和大总结继续要求固定标题、固定 `【历史分发】` 栏目及固定字段顺序；事实内容、宿主选择和颗粒度判断仍由总结提示词结合权威世界书与正文决定。
- 请求层删除“小总结协议或无”“大总结协议或无”的冲突表述；存在 pending 来源时禁止返回“无”。
- 模型返回非空但固定协议无法识别时，只执行一次独立 `summaryRepair` 格式恢复请求；第二次仍失败则整体回滚，不无限重试。
- 格式恢复只允许归一化标题、栏目、标点、换行与字段顺序。修复结果中的来源、目标、栏目、事实或处理结论无法在原返回中找到时，机械拒绝，防止借格式修复补写语义。
- 自动小总结新增“关键变化最小间隔”，默认 5 回合。关键变化达到阈值也不能在不足最小间隔时触发；普通轮数阈值默认仍为 10 回合。
- ui.61 的确定性结算、幂等回读、无裁剪 pending、逐来源历史分发和父事务回滚保持不变。

详细实现见 `PATCH-SCOPE-UI62.md`、`UI62-FIXED-SUMMARY-CONTRACT-VALIDATION.md` 与 `UI62-REALTEST-CHECKLIST.md`。

## 2.0.0-lite.ui.61-deterministic-settlement 本轮改动

- 小总结和大总结不再接受“暂不处理”。每个有效 pending 来源必须明确选择“吸收”或“保留完成”。
- 证据不足、对象仍在运行、当前场景或受保护对象统一使用“保留完成”，结束本次颗粒度判断；以后发生真实变化时由提取链重新加入 pending。
- “保留完成”新增无写入短格式：`来源：类型｜名称；处理：保留完成`，避免为了结束判断而虚构事实。
- 模型返回“无”、遗漏来源、混合处理值或出现无法解析的历史分发行时，整次总结视为协议失败；不执行部分写入，也不扣除 pending。
- 目标事实已经在权威世界书中存在时，可通过同一轮来源映射和权威回读幂等完成保留或吸收，不要求为了制造删除证明而重复写入。
- 总结完成判断但没有世界书变化时，仍重置对应总结调度周期，避免达到阈值后每轮重复请求模型。
- pending UID 不再按 96/128 上限静默裁剪；队列只通过确定完成、成功吸收或来源已不存在而缩减。
- 来源未通过最终退出或完成证明时，继续保留在 pending，状态显示为未完成，不冒充本轮已经结算。
- ui.60 的逐来源历史分发、临时 NPC/物品受限沉降、性格提炼链，以及 ui.59 的父事务、回滚和 UI 联动修复全部保留。

详细实现与实机验证步骤见 `PATCH-SCOPE-UI61.md`、`UI61-DETERMINISTIC-SETTLEMENT-VALIDATION.md` 和 `UI61-REALTEST-CHECKLIST.md`。

## 2.0.0-lite.ui.52-summary-granularity

- 小总结不再从“第一个活动事件”开始选材，而是以上次小总结后提取链实际新建或更新的世界书 UID 集合作为主工作集。
- 聊天级游标只保存待整理 UID 集合，不复制剧情正文，不建立第二数据库；小总结成功后清空本期集合，并把其实际改动 UID 交给大总结阶段。
- 小总结输入改为三层：整本权威世界书轻量索引、本期实际变更条目完整内容、直接关联条目完整内容；场景仅作为对象、目标、因果、时间和规则范围之外的一项关联维度。
- 小总结提示词按“核心锚点—处理路径—颗粒度边界—重点规则—唯一格式—示范”模板重写，职责固定为把细颗粒提取内容抽象为适合继续游玩的较粗运行结构。
- 大总结按相同模板重写，职责固定为把小总结后的运行条目进一步抽象为跨场景、跨阶段或明确永久成立的长期事实、历史结果和系统规则。
- 明确支持剧情中一次正式建立的新规则：是否进入场景、世界或基础设定由确定性与实际作用范围决定，不以机械出现次数为准；猜测、传闻和无解释异常不得晋升。
- 新增受限的事件来源吸收协议。小总结只有在目标事件同时获得粗颗粒分发事实时，才能声明某个工作集内、未锁定且非焦点的细事件壳被完整吸收；写入目标成功后才删除来源，失败可通过提交回执整体回滚。
- 人物、场景、物品、世界和基础设定本轮只做重新分发与栏目更新，不执行模型驱动的整条删除，避免过度清理。
- ui.51 的完整权威世界书提取索引、原 ENTRY 协议、API Profile、审核修正、事务、回执、回滚和原生召回链保持不变。
- 本地新增 `summary-granularity.test.mjs`，覆盖实际变更选材、完整索引、提示词边界、规则首次建立、事件吸收安全闸门和旧内置提示词迁移。

详细实现范围见 `PATCH-SCOPE.md`，固定验证见 `SUMMARY-GRANULARITY-VALIDATION.md`。

## 2.0.0-lite.ui.55-natural-protocol-recovery 本轮改动

- 审核输出由强制 `PASS/FAIL` 改为自然中文：`审核结论：通过` 或 `审核结论：需要修正`。解析器继续兼容旧 `PASS/FAIL`、`通过/不通过`、自然句“未发现违规”“需要修正”等常见输出。
- 审核第一次返回仍无法解析时，插件会进行一次独立的自然格式重试；修正正文、世界书和处理游标在结论确认前均不改变。
- 提取输出改为无闭合符号的自然中文条目：单独一行 `条目`，随后填写 `类型`、`名称`、`关键词` 和各栏目。模型不再需要正确拼写 `<<<ENTRY>>>`、`<<<CONTENT>>>`、`<<<END_ENTRY>>>`。
- 本地解析器兼容多种常见写法：新自然格式、`条目：人物｜名称`、`人物：名称`、`条目：人物` 后接名称，以及旧版严格 ENTRY 协议。
- 提取模型第一次输出为自然文本但格式不完整时，格式修复器也使用同一自然中文格式；只有两次均无法形成安全条目时才停止写入。
- 用户可见错误由“缺少 ENTRY 标记”改为“缺少可识别的条目起始行”，避免把内部协议术语当成唯一有效格式。
- 新增 `natural-protocol-recovery.test.mjs`，覆盖自然审核结论、自然提取格式、旧协议兼容、冒号标题、分行类型/名称和多行关键词。

真实 SillyTavern 中不同第三方模型的自由输出仍需实机验证；本版本未降低事实归属、栏目合法性、八条上限、事务提交和回滚校验。

## 2.0.0-lite.ui.56-granularity-ladder 本轮改动

- 小总结的来源吸收从“仅事件→事件”扩展为受限颗粒度升阶：事件可并入更粗事件，已离开的小场景可并入更大的场景或世界。
- 小场景升阶不只保留固定事实，还必须抽象出宏观事件痕迹、持续环境/设施/路线影响，以及以后再次进入时仍成立的运行条件。
- 被完整承接的小场景壳退出；玩家以后再次进入该地点时，提取链根据当时权威世界状态重新创建新的高分辨率场景壳。
- 大总结继续扩大颗粒度：事件可升阶为更粗事件或世界历史，场景可升阶为世界结构，区域级世界条目可并入更宽世界条目。
- 每次升阶都必须同时保留“谁参与、发生了什么性质的事情、最终结果、持续影响”，并消费已经被完整承接的低层运行壳，禁止只叠加一层重复摘要。
- 吸收安全条件收紧为实际待总结 UID 工作集；直接关联条目即使被模型写入吸收协议，也不会被删除。
- 当前场景、人物、物品、基础设定、锁定条目、焦点条目和非镜渊管理条目禁止作为吸收来源。

## 2.0.0-lite.ui.57-scene-recall-stability 本轮改动

- 修复小总结或大总结同时更新多个场景后，召回字段投影再次刷新 `updatedAt`，导致场景阶段在提交前后漂移的问题。

## 2.0.0-lite.ui.59-cross-module-repair 本轮改动

- 小总结与大总结不再整批清空待处理 UID；只扣除实际吸收、已确认重写或已经不存在的来源，当前场景、锁定和焦点对象继续保留。
- 待处理 UID 全部失效时直接停止，不再回退总结无关的近期条目。
- “整理世界书”改为单一父事务：小总结、大总结或召回重排任一步失败／取消，恢复操作前世界书、游标、回执和游戏时间；中途切换聊天时保留原聊天事务标记，返回后优先恢复。
- 完整处理在审核修正后若提取失败，会反向恢复原正文，避免“正文已改、整体显示失败”的半完成状态。
- 回执记录提交前后游标与游戏时间；正文编辑、切换或删除触发回滚时同步恢复完整状态。
- 总结吸收删除必须满足同一事务目标写入和事实级承接证明；临时 NPC 与当前事件总结的无证明机械删除暂时关闭。
- 自动任务、手动任务和维护任务统一进入一个 UI 忙碌状态；任务运行时设置不可编辑，取消按钮能识别后台任务。
- 世界书页使用一次权威读取同时渲染管理状态与召回映射；聊天切换会清除旧预览并重新绑定消息 DOM。
- UI 将“整理世界书”设为主入口，单级总结收入高级控制，API 探针移到设置页；移动端交互按钮统一到至少 44px。
- 新增 `cross-module-repair.test.mjs`，覆盖精确 pending、完整状态回滚、父事务、正文反向恢复、删除证明、单次读取、统一任务状态和预览隔离。

本地固定测试通过不等于 SillyTavern 实机验收；当前主题、Android 消息 DOM、触屏布局和真实模型输出仍需实机复验。
