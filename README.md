# Mirror Abyss 2.0.0-lite.ui.27

面向 SillyTavern 1.18 的轻量正文审核、事实提取、事件结算、总结沉降与世界书活动包扩展。

本版继续以 **SillyTavern 聊天世界书作为唯一长期数据源**。没有第二剧情数据库、图数据库、持久 Outbox、全局人物状态机或独立时间数据库。


## ui.27 三维世界书治理与活动包

- 世界书条目继续使用可读正文，同时由插件维护最小治理元数据：当前场景/游戏时间、直接关联、仓库或运行态角色。这些字段用于分发、沉降、管理预览和活动包编译，不形成第二份剧情事实。
- 当前游戏时间只保存聊天当前值。历史先后继续由 `S001、S002……` 场景锚点承担；插件不写现实时间，也不建立双时态数据库。
- 小型状态转换表只约束当前事件：活动、受阻、完成、终止和归档。完成事件不能被总结或后续同名候选重新打开；人物是否当前由场景、活动事件和焦点动态投影。
- 当前场景离开时自动结算动态栏目；固定设施与明确固定岗位保留。临时 NPC、泛称路人和一次性工作人员不创建人物主档；固定岗位在场景中按角色类型归并。
- 人物条目保护身份、性格核心、表达方式、决策倾向、关系立场和当前状态。场景固定角色最多5类、固定设施最多8项；事件参与者最多6项、附属人员最多4类。
- 单条目字数由类型和有效复杂度计算。模型请求先收到栏目与长度约束，插件端再做去重、容量收束和语义边界压缩；仍不能安全满足硬上限时拒绝提交。
- `运行包｜当前活动` 是唯一自动发送的镜渊条目。它从仓库确定性选取核心规则、当前时空、当前场景、现场人物、当前事件、生效规则和必要历史，并在总预算内合并去重。
- 控制面板新增“管理”页，可查看当前/沉降人物、场景固定内容、活动事件、最终活动包、分区字数及数据健康问题。
- 可在设置中关闭活动包模式；关闭后恢复 ui.26 的原生召回规划，不保留旧活动包。
- 自动化回归：105/105 通过。


## ui.26 场景锚点与提炼重建

- 重建先把来源事实按连续剧情节点聚合为场景锚点，再进行对象归属；首次建立的正式锚点由插件按游戏内时间顺序编号为 `S001、S002……`；再次重建时优先复用已有 `S` 锚点，新增或拆分节点再分配未占用编号，模型不能自造最终编号。
- 每个锚点保存游戏时间、地点和时间来源。明确日期或时段直接使用；由“次日、当晚、数日后”等关系推出的时间标记为推定；没有证据时固定为未知。模型补造的时间或地点会在本地降级为未知。
- 重建条目标题从主要场景锚点派生，例如 `事件｜S014-E01｜林言发烧与康复`。人物、场景、物品、事件、世界和基础规则分别使用 `C/L/I/E/W/R` 类型码；自定义类型使用 `X`；标题解析和后续匹配会剥离编号。
- 提炼改为最小事实集：同义重复、包含式重复、过程性复述和无后续价值动作只保留一份或安全丢弃；一条新事实可以显式承接多条重复来源行。
- 已结束场景、旧在场名单、过期资源和已解除状态会从动态栏目转入过去完成态，不再继续占用人物【当前】、场景【当前状态/在场/当前资源】或物品【当前】。
- 运行规则只在来源明确陈述制度、约定、条件或限制，或者至少两个不同场景锚点反复证明同一机制时成立。单次行为不能升级为长期规则。
- 每个重建条目新增【时空锚点】区块，并在扩展元数据中保存锚点、游戏时间、地点、时间来源和时态；来源事实行覆盖保护继续负责防止提炼时丢失有效事实。
- 自动化回归：94/94 通过。


## ui.25 核心链路闭合

- 核心提取、总结、重建、设定导入、条目编辑、焦点修改和召回重排共用同一聊天级串行队列，排队任务与维护操作不会并发写世界书。
- 普通世界书提交只保存一次：新内容写入、被消费条目删除和原生召回字段重排在同一内存快照中完成；保存失败时旧表保持不变。
- 人物、场景和物品的动态栏目按正文结束时完整快照整段替换，旧位置、伤势、目标、在场名单和资源状态不会因字段缺省继续残留。
- 小总结和大总结只有在标准长期栏目至少存在一条有效事实时才允许提交；全空格式与单独“无”均为零写入。
- 两级总结的旧容器与活动事件具有固定输入席位；总结计数只在真实写入后重置。
- 世界书重建按来源事实行核验覆盖。遗漏身份、规则、状态或附属对象事实会先补入目标安全栏目，来源旧条目才可删除。
- 轻量提交回执默认不设固定条数上限；回执元数据保存失败时，本次世界书提交立即自动回滚。回执仍只保存条目差异，不保存聊天正文。
- 自动化回归：88/88 通过。


## ui.24 记忆生命周期与请求调度收束

- 每轮提取改为状态变化优先：普通走动、落座、开关门、视线、短暂表情和当轮恢复的小变化在建立事件前过滤。
- 事件统一为【参与】【场景】【已发生进展】【未发生进展】【结果】【别名】；旧【目标】【阶段】【关键进展】【未决】只用于兼容读取，不再写回可召回正文。
- 【未发生进展】只保存已经发生但未造成状态变化、且短期连续性仍需要的材料；它不是未来任务、待办或未决目标，最多保留两行，并在压缩时吸收、改投或清除。
- 小总结改为当前事件压缩与稳定影响分发。新快照写入成功后，消费已被覆盖的旧过程栏目。
- 大总结改为覆盖式长期沉降，只接收压缩后的稳定变化、重要事件结果、长期关系和稳定世界影响；不再累计复述小总结或事件流水。
- 历史重建采用一次全局来源规划，再按上下文容量把多个候选组联合装入请求；18个独立对象的回归用例由20次模型调用降为6次。
- 取消最终整表模型审核，改用本地来源覆盖、身份冲突、场景边界、重复宿主、空壳和栏目校验。
- 单个联合批次遗漏或格式失败时，相关旧条目原样保留；其他成功结果仍可形成预览和提交，不再形成失败重试锁。
- 同一次重建的新条目使用 `类型｜R批次-序号｜稳定名称` 标题；匹配、去重和别名识别会忽略编号。
- 场景匹配增加稳定名称、别名、房间号、地点类型和名称相似度对齐，降低模型改名造成的重复地点。
- 控制面板顶部栏与分页栏改为不透明固定背景，滚动时正文不再透过顶栏。
- 自动化回归：82/82 通过。

## ui.21 调整

本版收紧人物认知栏目并隔离模型控制层。

- 旧世界书中的该控制条目及其 `世界｜重建待确认` 归档副本，会在下一次重建时移除且不会发送给模型。

- 过滤只针对插件控制协议，不按普通“规则”“禁止”等词泛删，真实世界规则仍可正常保存。

## ui.19 调整

本版替换世界书重建的模型发送方式。重建不再先按模糊关联重复拆批、平均裁剪旧条目，再依赖结果端文本去重。

- 第一阶段发送精简全局来源索引：旧 UID、原类型、稳定标题、栏目和带临时编号的事实行；本阶段只规划归属，不重写正文。
- 每条来源行在规划中只能归入一个候选组，或明确丢弃；不会同时发送给人物、事件、世界等多个批次。
- 真身、假身、替身、分身、载体、不同稳定场景和不同事件目标在发送正文前完成分组。
- 第二阶段一次只处理一个对象或一条事件生命周期；请求只包含已经分配给该组的完整来源行，不携带其他对象正文。
- 长组按互不重叠的来源行片段发送；同一来源行不会因分片重复出现。
- 事件判断可读取“尚未发生、待确认、未解决”等来源证据，但最终条目仍只保存阶段、关键进展和结果。
- 世界与基础设定不再作为第二次全类型重建入口；具体人物、物品、场景和事件事实在规划阶段直接迁往权威宿主。
- 每个模型候选保留临时来源行引用；这些引用只存在于当前重建任务内，不写入长期世界书。
- 第三阶段只发送精简候选目录和对应来源行做结构校验；重复对象、身份形态混淆、场景串档、错误事件状态和空壳会阻止生成可提交预览。
- 规划、单组重建和最终校验均支持原有限流退避与断点续跑；仍不建立第二剧情数据库或长期事实注册表。
- 使用用户上传的真实世界书验证：54 个镜渊条目生成 332 条来源行，规划输入约 1.68 万字符，在 2.8 万字符预算内完整发送，没有发生中间截断。
- 自动测试更新为 66 项，全部通过。

## ui.18 调整

本版在 ui.17 的轻量语义核心上，集中修复旧世界书重建。插件仍不建立第二剧情数据库。

- 世界条目只运行一次全局收束，不再按组织、地区和局势重复拆分请求。
- 基础设定只运行一次规则收束；别名空壳会从有效旧 UID 恢复规则正文。
- 旧“重建待确认”档案按【来源条目】恢复原类型，基础规则不再被当成世界条目。
- 事件按生命周期聚合；已有阶段结果不等于事件已经结束。
- 同名真身、假身、分身和替身保持独立身份，并生成稳定区分标题。
- 场景只允许同一稳定地点互为别名，避免酒馆、决斗台和遗迹入口错误合并。
- 全局去重按来源、事实等价和权威宿主执行，删除重复子项与换角度重复。
- 低价值个人物品和简单公用设施分别并入人物与场景；关键物品继续独立保存。
- 未被可靠覆盖的旧条目按原标题禁用保存；空正文不再生成待确认条目。

ui.17 已有的审核、完整回合提取、当前快照、固定事实、轻量回执和焦点控制继续保留。

- 审核改为上下文白盒规则：不读取角色卡或世界书，玩家可在设置页直接编辑审核提示词；插件只提供默认基础规则与严格 PASS/FAIL 解析。
- 审核读取本轮玩家输入与 AI 最终回复；普通提取只以审核后的 AI 最终回复为事实目标，玩家输入与前文仅用于指代、承接和因果理解。
- 流式分段、重复渲染和下一轮正文不会打断上一轮已经通过审核的提取；审核失败立即标记并等待修正文。
- 旧【持续经历】【持续变化】【世界变化】统一为【固定事实】；固定事实超限时压缩较早结果并保留近期结果，不再只截掉中间经历。
- 【当前】与【当前状态】保存正文结束时的完整快照；同义状态槽只保留最终值，明确“无”可以清空。
- 普通个人附属物直接并入人物【持有】；公用或共享物品进入场景资源；只有唯一、跨场景或具有独立状态的物品保留独立条目。
- 独立物品作为权属、持有和位置的权威宿主。人物只保存最短持有引用，场景资源按物品最终位置同步；公用临时用具不会强行写进人物卡。
- 物品的所有权、保管者、当前持有者、当前使用者、使用权限和当前位置分别保存。
- 名称只用于寻找候选；种族、编号、型号、职业、组织等身份锚点冲突时禁止合并，并自动生成带区分锚点的稳定标题。
- 跨条目去重按主体、关系与值判断，避免同一事实换角度重复，也避免不同关系因值相同而互相误删。
- 每轮保留正文结束时的最终结果，不把拔出、掉落、拾起、收回等过程分别写成长线状态。
- 世界与基础设定在有限提取上下文中保留固定席位，减少被人物和物品候选挤出。
- 每个聊天保存轻量世界书差异回执，默认不设固定条数上限。编辑、删除或切换 Swipe 时逆序回滚受影响提交并重新排队；回执不保存聊天正文，也不建立第二事实源。
- 召回面板的人物条目提供“设为焦点 / 取消焦点”；焦点只改变召回和保护状态。

回执仅用于撤回由当前聊天正文产生且之后未被其他操作改写的提交；无法安全自动回滚时，使用“世界书重建”重新收束。

## 现行更新范围

本包保留既有外围基础设施，当前集中维护以下链路：

- AI 辅助世界书重建；
- 角色认知来源约束（仅存在于请求控制层）；
- 同一事件生命周期聚合；
- 后台任务固定源正文快照。

世界书重建先生成预览，不直接修改旧表。规划阶段先建立场景锚点与游戏时间，再完成去重提炼、时间态沉降和规则抽取；提交时写入并回读新结构，校验通过后才消费已被来源事实行完整承接的旧镜渊条目，失败时恢复旧表。用户手写且未受镜渊管理的条目不参与删除。

人物认知分为【已知】和【误信】。【已知】包含人物通过明确渠道获得的事实、怀疑、判断和推理；【误信】仅用于已有明确证伪依据但人物仍相信的错误认知。世界事实不自动等于角色已知；每条人物认知必须保留亲眼观察、听到对白、收到消息、查看记录、他人转述、亲身经历、可靠推理、特殊能力、公开信息、自身身份、自身行动或直接告知之一。

同一事件按目标、参与者、场景和未决因果持续更新。标题变化、动作推进和场景内移动不会单独建事件；目标与因果独立、能够单独结束的过程仍保持独立。

后台提取和总结固定读取被触发时的源正文。生成下一条正文只会把新任务放入同一聊天队列，不会取消正在运行的旧任务。

## 六类业务条目

模型只能输出：

- `人物`：身份、稳定能力、当前状态、该人物自身的关系、关键持有物和固定事实；
- `场景`：稳定空间知识、当前局部快照与关联入口；
- `物品`：关键物品的定义、功能、位置、持有者、状态和限制；
- `事件`：多对象过程、必要因果、阶段、未决事项和结果；
- `世界`：会随剧情变化、但影响范围超出单一人物或单一场景的区域、组织、权力、制度、资源网络和公开局势；
- `基础设定`：不随普通剧情变化的世界常识、自然规则、种族共性、能力技术、社会规则和地理框架。

不再创建独立的关系或地点条目；“全局 / 全局状态 / 世界局势”统一归入世界：

```text
关系事实 → 写入对应人物【关系】
地点知识 → 写入对应场景
全局状态与变化 → 写入世界条目
稳定世界框架 → 写入基础设定条目
```

基础设定是正式的第六类内容条目，并以常驻、递归隔离方式召回；长期焦点仍是任意条目的召回属性。

## 身份未明人物

正文没有明确说明陌生人、匿名账号、蒙面者或未知声音是谁时，插件不得把它猜成现有人物。只有该对象已经产生会持续影响后续的状态、关系、持有物、行动结果或未决联系时，才建立临时人物档。

临时档使用可观察称呼，并写入 `身份未明` 与 `临时` 管理关键词。相同对象后续继续更新该档；正文明确揭示真实身份后，临时档合并进已知人物主档并删除。两个无法可靠区分的陌生对象不会仅凭“都是陌生女人”而强行合并。

## 场景中心结构

场景负责组织局部世界，但不保存事件流水。

场景固定格式：

```text
【定义】
【空间结构】
【固定资源】
【固定事实】
【当前状态】
【在场】
【当前资源】
【活动关联】
【世界影响】
【局部约束】
【别名】
```

其中：

- `定义 / 空间结构 / 固定资源 / 固定事实`会随探索和事件结果补全；
- `当前状态 / 在场 / 当前资源 / 活动关联 / 世界影响 / 局部约束`是正文结束时的完整当前快照；
- 同一稳定地点持续更新同一场景条目；
- 单轮提取最多一个场景，并且必须是正文结束时实际所在的当前场景；
- 被提及但没有实际进入的地点不会被误标为当前场景。

场景知识可以越来越完整，但栏目按用途分层：当前快照允许最多信息，稳定结构只保留必要事实，固定事实按较早摘要与近期结果分层保存。动作流水、对话复述和过程链不会继续累积。详细规格见 `SCENE_POLICY.md`。

## 事件与直接分流

事件是唯一过程和结算容器。

已经成立且宿主明确的事实直接写入对应条目：

```text
人物受伤 → 人物【当前】
物品遗落 → 物品【当前】
场景出口坍塌 → 场景【固定事实】
王国开始公开通缉 → 世界【公开局势】；制度已经成立时补充【固定事实】
```

事件只保留形成这些事实的必要因果和阶段节点，不复制对象条目的完整状态。事件结束后，小总结或大总结只分发仍然持续有效的影响；有历史价值的事件转为纯向量历史，无独立价值的事件容器可以退出。

换场景与事件结束互相独立：进入新场景不等于旧事件已经结束，同一场景内也可以先后结束和开始多个事件。

## 世界与基础设定

`世界`用于会变化的宏观状态：区域范围、跨场景地理关系、组织结构、控制权、现行制度、资源与交通网络、公开局势和持续影响。它不要求本轮已经实际跨越多个场景；只要正文明确说明该事实会作用于场景外对象或后续多个地点，就可以在普通提取阶段创建。

`基础设定`用于稳定框架：世界常识、自然规则、种族与生命、能力与技术、社会规则和地理框架。明确出现的新设定会在普通提取阶段主动创建，不再等待大总结。

世界【固定事实】保存已经形成的宏观结果；【持续影响】保存仍在作用的明确对象或区域。

## 场景中心召回

召回方式由代码根据条目角色和场景距离确定，模型不能输出常驻、关键词、向量、递归、深度或顺序。

| 条目 | 激活方式 | 可被递归带出 | 激活后继续关联 |
|---|---|---:|---:|
| 基础设定 | 常驻 | 否 | 否 |
| 长期焦点 | 常驻 | 否 | 否 |
| 当前场景 | 常驻 | 否 | 是 |
| 上一场景 | 关键词 | 否 | 是 |
| 远期场景 | 纯向量 | 否 | 是 |
| 活动事件 | 关键词 | 是 | 否 |
| 普通人物 | 关键词 | 是 | 否 |
| 关键物品 | 关键词 | 是 | 否 |
| 世界状态 | 关键词 | 是 | 是 |
| 关闭事件/历史总结 | 纯向量 | 否 | 否 |

场景迁移：

```text
最新场景 → 当前场景，常驻
次近场景 → 上一场景，关键词
更早场景 → 远期场景，纯向量
```

纯向量条目会清空真实关键词；当前场景、长期焦点和基础设定也不会同时保留关键词或向量。普通人物、物品和活动事件被场景带出后立即停止递归。只有场景与世界状态可以继续关联。

面板中的魔杖按钮可对既有镜渊管理条目执行“重新规划召回状态”。该操作不调用模型、不修改条目正文，只重算 SillyTavern 原生召回字段。

## 关键词控制

每条最多四个真实关键词，只保留：

- 稳定名称；
- 唯一别名；
- 明确专名或唯一称谓。

代码会删除类型词、泛词和描述性人物称呼，例如“人物、场景、事件、女孩、少女、房间、当前局势”等。`海蓝发少女`这类描述不会作为长期触发词。当前场景与纯向量条目的候选关键词只暂存在镜渊扩展字段中，方便以后恢复为上一场景关键词，不参与当前触发。

## 提取语法

```text
<<<ENTRY:类型:稳定名称>>>
<<<KEYWORDS>>>
- 稳定名称
- 唯一别名
<<<CONTENT>>>
【固定小标题】
- 精简事实
<<<END_ENTRY>>>
```

要求：

- 只记录正文已经成立且仍会影响后续的事实；
- 不写“供 AI 参考”、证据等级、推测、预测或剧情建议；
- 同一事实只有一个主要宿主；
- 每条事实尽量不超过 80 字；
- 每个小标题按语义预算限制；当前快照最大，固定事实次之；
- 单次最多 8 条，其中场景最多 1 条；
- 有效条目部分提交，异常片段单独隔离；
- 一个安全条目都无法恢复时，才额外调用一次格式修复模型。

## 审核后的正文替换

审核失败后，正文替换由 `HostAdapter.replaceAssistantText` 单点完成：

1. 校验聊天、消息索引、消息键和原正文哈希；
2. 同步 `message.mes` 与当前 swipe；
3. 清除可能遮挡正文的 `extra.display_text`；
4. 刷新消息并等待保存；
5. 回读正文、swipe 和显示缓存；
6. 任一校验失败即恢复原正文。

自动提取会等待替换完成，然后读取修正版正文。

## 504 控制

模型请求由独立轻量模块管理：

- 审核、修正、提取、格式修复和总结分别使用不同输出预算；
- 正常提取最多携带 5 个相关世界书条目，精简重试最多 3 个；
- 只有 502/503/504、HTML 网关页、`No message generated` 和明确网络错误使用精简提示词重试一次；
- 格式错误、聊天切换、用户取消和快照失效不会重试。

详见 `AUDIT_504.md`。

## 官方 Connection Profile

“镜渊处理 API”下拉框直接调用 SillyTavern 官方 Connection Profile 服务：

- 选择“当前 SillyTavern 连接”时继续走 `generateRaw()`；
- 选择某个 Profile 后，审核、修正、提取、小总结和大总结统一使用该 Profile；
- 不切换主聊天 API；
- 插件只保存 Profile ID，不保存 API Key、服务器地址、模型或预设正文。

## UI

入口是浏览器右侧中部的 44px 浮动圆形图标。召回区域显示：

- 当前、上一和远期场景；
- 焦点与基础设定；
- 世界状态；
- 常驻、真实关键词和纯向量；
- 关联入口、双向关联、关联终点和递归隔离；
- 角色定义前、角色定义后或对话深度；
- Order 与 Scan Depth。

UI 回读真实世界书字段，不使用“证据/存疑”层，也不自行决定调度。

## 分页面板与最终态回读

面板分为三个页面：

- `运行`：手动操作、队列与阶段状态；
- `召回`：世界书召回映射，每页 12 条；
- `设置`：Connection Profile、自动开关与总结阈值。

提取成功不会立即触发 UI 回读。插件会等待提取提交、自动总结和召回重排全部结束，再回读一次最终世界书，避免页面短暂显示旧数据或中间数据。

本地测试覆盖语法、正文替换、上下文白盒审核、异步队列、近期撤回回滚、最终状态收束、物品宿主路由、人物—物品—场景轻量协调、同名身份冲突、固定事实压缩、六类提取、世界与基础设定保留、总结分发和召回 UI。

本地测试不能替代用户云端 SillyTavern、真实 Connection Profile、Vector Storage 配置和移动端主题。实机首次安装后，建议在面板点击一次“重新规划召回状态”，再观察三次连续换场景后的字段变化。


## ui.12 内容边界

- 浮动入口可拖动，位置只保存在浏览器本地。
- 物品条目只记录单个可追踪实例；同类集合保留在场景资源。
- 人物描写只保留少量影响识别、能力或剧情判断的客观特征。


## ui.13 小标题归一

二次提取前，插件会按条目类型统一同义小标题：

- 人物、物品：`【当前状态】`、`【状态】`统一为`【当前】`；
- 场景：`【当前】`、`【状态】`统一为`【当前状态】`；
- 事件：`【当前】`、`【当前状态】`统一为`【阶段】`；
- 世界：`【当前】`、`【当前状态】`统一为`【公开局势】`。

旧条目同时存在两个同义栏目时，同一状态槽保留正文中后出现的值。条目下一次被更新时，会自动保存为唯一规范小标题，不调用额外模型。

## ui.14 子条目分层、匹配收敛与分页

- 当前快照栏目拥有最高预算；身份、稳定、关系、持有等栏目使用较小预算；持续经历、持续变化、关键进展、结果、世界变化和持续影响只保留一条已发生结果。
- 人物称谓变体、已登记别名和正文明确揭示的伪装身份会命中原档。
- 同名重复档会选择主档、合并有效内容并删除副档。
- `位置/所在地/当前地点`统一为`当前位置`，`目标/当前目标/目的/计划`统一为`当前目标`。
- UI 只回读最终世界书；面板拆为三页，召回列表每页 12 条。


## ui.15 未知身份与主动全局建档

- 未揭示身份时建立独立临时人物档，不命中已知人物。
- 身份揭示后把临时档合并进已知人物主档并删除。
- 世界和基础设定都可以在普通提取阶段主动创建。
- 世界字段扩大到区域、组织、权力、制度、资源与交通和公开局势。


## 世界书重建请求调度

世界书重建属于一次性迁移，允许多次模型调用。第一阶段只规划来源行的唯一宿主、场景锚点、游戏时间和地点；插件按可比较的游戏时间排序并分配正式 `S` 编号。第二阶段按锚点提炼最小事实、判断当前/持续/已完成/已结束/长期时态并抽取有证据的运行规则。插件将候选拆成串行小批次，默认每批间隔 2.2 秒；遇到 429 会退避等待。每批成功后保存内存断点，失败后再次点击只继续未完成批次。普通游玩中的审核、提取和总结调用方式不受此机制影响。
