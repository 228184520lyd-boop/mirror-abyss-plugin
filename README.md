# Mirror Abyss 2.0.0-lite.ui.11

面向 SillyTavern 1.18 的轻量正文审核、事实提取、事件结算、总结沉降与世界书召回扩展。

本版继续以 **SillyTavern 聊天世界书作为唯一长期数据源**。没有第二剧情数据库、Runtime、持久 Outbox、事务模拟、Reconciler 或大型状态机。

## 五类业务条目

模型只能输出：

- `人物`：身份、稳定能力、当前状态、该人物自身的关系、关键持有物、持续经历；
- `场景`：稳定空间知识、当前局部快照与关联入口；
- `物品`：关键物品的定义、功能、位置、持有者、状态和限制；
- `事件`：多对象过程、必要因果、阶段、未决事项和结果；
- `世界`：跨多个场景持续生效的整体变化、权力、制度和公开局势。

不再创建独立的关系、地点或全局条目：

```text
关系事实 → 写入对应人物【关系】
地点知识 → 写入对应场景
全局变化 → 写入世界条目
```

基础设定仍是独立常驻规则条目；长期焦点是任意条目的召回属性，不是第六种内容类型。

## 场景中心结构

场景负责组织局部世界，但不保存事件流水。

场景固定格式：

```text
【定义】
【空间结构】
【固定资源】
【持续变化】
【当前状态】
【在场】
【当前资源】
【活动关联】
【世界影响】
【局部约束】
【别名】
```

其中：

- `定义 / 空间结构 / 固定资源 / 持续变化`会随探索和事件结果持续补全；
- `当前状态 / 在场 / 当前资源 / 活动关联 / 世界影响 / 局部约束`是正文结束时的完整当前快照；
- 同一稳定地点持续更新同一场景条目；
- 单轮提取最多一个场景，并且必须是正文结束时实际所在的当前场景；
- 被提及但没有实际进入的地点不会被误标为当前场景。

场景知识可以越来越完整，但每个栏目有确定性行数预算。空间骨架与最新发现同时保留，动作流水和重复描述不会无限膨胀。详细规格见 `SCENE_POLICY.md`。

## 事件与直接分流

事件是唯一过程和结算容器。

已经成立且宿主明确的事实直接写入对应条目：

```text
人物受伤 → 人物【当前】
物品遗落 → 物品【当前】
场景出口坍塌 → 场景【持续变化】
王国开始公开通缉 → 世界【公开局势】或【世界变化】
```

事件只保留形成这些事实的必要因果和阶段节点，不复制对象条目的完整状态。事件结束后，小总结或大总结只分发仍然持续有效的影响；有历史价值的事件转为纯向量历史，无独立价值的事件容器可以退出。

换场景与事件结束互相独立：进入新场景不等于旧事件已经结束，同一场景内也可以先后结束和开始多个事件。

## 场景中心召回

召回方式由代码根据条目角色和场景距离确定，模型不能输出常驻、关键词、向量、递归、深度或顺序。

| 条目 | 激活方式 | 可被递归带出 | 激活后继续关联 |
|---|---|---:|---:|
| 基础设定 | 常驻 | 否 | 否 |
| 长期焦点 | 常驻 | 否 | 否 |
| 当前场景 | 常驻 | 否 | 是 |
| 上一场景 | 关键词 | 否 | 是 |
| 远期场景 | 纯向量 | 否 | 是 |
| 活动事件 | 关键词 | 是 | 否 |
| 普通人物 | 关键词 | 是 | 否 |
| 关键物品 | 关键词 | 是 | 否 |
| 世界变化 | 关键词 | 是 | 是 |
| 关闭事件/历史总结 | 纯向量 | 否 | 否 |

场景迁移：

```text
最新场景 → 当前场景，常驻
次近场景 → 上一场景，关键词
更早场景 → 远期场景，纯向量
```

纯向量条目会清空真实关键词；当前场景、长期焦点和基础设定也不会同时保留关键词或向量。普通人物、物品和活动事件被场景带出后立即停止递归。只有场景与世界变化可以继续关联。

面板中的魔杖按钮可对既有镜渊管理条目执行“重新规划召回状态”。该操作不调用模型、不修改条目正文，只重算 SillyTavern 原生召回字段。

## 关键词控制

每条最多四个真实关键词，只保留：

- 稳定名称；
- 唯一别名；
- 明确专名或唯一称谓。

代码会删除类型词、泛词和描述性人物称呼，例如“人物、场景、事件、女孩、少女、房间、当前局势”等。`海蓝发少女`这类描述不会作为长期触发词。当前场景与纯向量条目的候选关键词只暂存在镜渊扩展字段中，方便以后恢复为上一场景关键词，不参与当前触发。

## 提取语法

```text
<<<ENTRY:类型:稳定名称>>>
<<<KEYWORDS>>>
- 稳定名称
- 唯一别名
<<<CONTENT>>>
【固定小标题】
- 精简事实
<<<END_ENTRY>>>
```

要求：

- 只记录正文已经成立且仍会影响后续的事实；
- 不写“供 AI 参考”、证据等级、推测、预测或剧情建议；
- 同一事实只有一个主要宿主；
- 每条事实尽量不超过 80 字；
- 每个小标题单轮最多 6 行；
- 单次最多 8 条，其中场景最多 1 条；
- 有效条目部分提交，异常片段单独隔离；
- 一个安全条目都无法恢复时，才额外调用一次格式修复模型。

## 审核后的正文替换

审核失败后，正文替换由 `HostAdapter.replaceAssistantText` 单点完成：

1. 校验聊天、消息索引、消息键和原正文哈希；
2. 同步 `message.mes` 与当前 swipe；
3. 清除可能遮挡正文的 `extra.display_text`；
4. 刷新消息并等待保存；
5. 回读正文、swipe 和显示缓存；
6. 任一校验失败即恢复原正文。

自动提取会等待替换完成，然后读取修正版正文。

## 504 控制

模型请求由独立轻量模块管理：

- 审核、修正、提取、格式修复和总结分别使用不同输出预算；
- 正常提取最多携带 5 个相关世界书条目，精简重试最多 3 个；
- 只有 502/503/504、HTML 网关页、`No message generated` 和明确网络错误使用精简提示词重试一次；
- 格式错误、聊天切换、用户取消和快照失效不会重试。

详见 `AUDIT_504.md`。

## 官方 Connection Profile

“镜渊处理 API”下拉框直接调用 SillyTavern 官方 Connection Profile 服务：

- 选择“当前 SillyTavern 连接”时继续走 `generateRaw()`；
- 选择某个 Profile 后，审核、修正、提取、小总结和大总结统一使用该 Profile；
- 不切换主聊天 API；
- 插件只保存 Profile ID，不保存 API Key、服务器地址、模型或预设正文。

## UI

入口是浏览器右侧中部的 44px 浮动圆形图标。召回区域显示：

- 当前、上一和远期场景；
- 焦点与基础设定；
- 世界变化；
- 常驻、真实关键词和纯向量；
- 关联入口、双向关联、关联终点和递归隔离；
- 角色定义前、角色定义后或对话深度；
- Order 与 Scan Depth。

UI 回读真实世界书字段，不使用“证据/存疑”层，也不自行决定调度。

## 验证边界

本地测试覆盖语法、正文替换、504 精简重试、异步顺序、场景内容累积、五类提取、关键词清理、场景迁移、纯向量清键、递归限制、总结分发和召回 UI。

本地测试不能替代用户云端 SillyTavern、真实 Connection Profile、Vector Storage 配置和移动端主题。实机首次安装后，建议在面板点击一次“重新规划召回状态”，再观察三次连续换场景后的字段变化。
