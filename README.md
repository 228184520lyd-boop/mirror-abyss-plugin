# Mirror Abyss 3.0.0-lite.ui.1 — 实机候选基准

本包是当前唯一运行基准。本文只描述当前标准，不保留历代实现规则。

## 1. 架构权责

- **世界书是唯一长期剧情事实源。** UI、召回、总结、管理视图都从世界书读取或确定性投影，不建立第二剧情数据库。
- **模型是唯一主要语义解释层。** 模型负责审核结论、事实语义、建立/变化/结束、总结抽象与人工合并语义。
- **插件只做确定性工作。** 包括固定协议校验、精确身份匹配、栏目模板、事务提交/回滚、SceneGroup 时间/谱系索引、召回映射和宿主边界校验。
- **正常运行不使用“新协议 + 旧协议兜底”。** 旧设置、旧 summary marks 只允许在升级读取时一次性迁移，迁移后不再成为运行标准。

## 2. 唯一模型协议

### 审核

```text
审核结论：通过
```

或：

```text
审核结论：需要修正
问题：
- 明确问题
```

不接受 PASS/FAIL 或自然语言猜测结论。

### 正文提取

```text
事实｜类型｜稳定名称｜建立｜关联对象｜完整事实
事实｜类型｜稳定名称｜变化｜关联对象｜完整事实
事实｜类型｜稳定名称｜结束｜关联对象｜完整事实
```

无事实只输出：

```text
无
```

正常提取只接受六类固定宿主：人物、场景、物品、事件、世界。基础设定只通过玩家世界设定导入/维护链进入，不由普通正文提取创建。

### 小总结 / 大总结 / 人工合并

三者共用同一个协议：

```text
写回｜类型｜稳定名称｜栏目名称｜事实
移除｜类型｜稳定名称｜栏目名称｜原事实
沉降｜来源类型｜来源稳定名称｜目标类型｜目标稳定名称
```

无操作只输出：

```text
无
```

栏目名称必须是对应宿主类型的当前标准栏目；不接受字段别名、箭头、逗号、Markdown 表格或其他替代协议。

### 玩家世界设定导入

只接受独立 ENTRY 协议：

```text
<<<ENTRY:类型:稳定名称>>>
<<<KEYWORDS>>>
- 关键词
<<<CONTENT>>>
【标准栏目】
- 完整事实
<<<END_ENTRY>>>
```

该协议只用于玩家设定导入，不是普通正文提取的备用格式。

### 世界书重建

重建阶段只接受当前 `【新条目】` 协议；正常运行不再尝试 JSON、旧 ENTRY 或自然文本重建格式。

## 3. 唯一栏目 Schema

人物、场景、物品、事件、世界、基础设定的标准栏目顺序由代码中的单一 `TYPE_SECTION_ORDER` 定义。

- parser 用它验证世界设定导入与总结栏目。
- 世界书模板归位用它规范栏目。
- 同一类型不再在不同模块维护不同栏目表。

旧世界书栏目别名只在读取旧数据时做确定性归一化，不属于模型输出协议。

## 4. SceneGroup 生命周期

- SceneGroup 只保存 UID、时间边界和谱系，不复制完整剧情正文。
- `memberUids` 是 SceneGroup 当前工作集唯一权威。
- 小总结队列只认 `closedEventTimelines[].summaryStatus`。
- 失败小总结不会阻塞后续 pending SceneGroup；玩家可精确重试失败场景。
- 大总结只由玩家手动触发。
- 大总结材料只来自已 settled SceneGroup，并由 `lastLargeSummaryAt` 表示正式消费水位。
- 不再维护 `pendingSmallSummaryMarks / failedSmallSummaryMarks / pendingLargeSummaryMarks` 等并行运行状态；旧字段仅升级时一次性迁移。

## 5. 模型连接与设置

- 只有一个 `modelProfileId`。
- 空值表示使用当前 SillyTavern 连接；非空表示统一使用一个 Connection Profile。
- 审核、修正、提取、小总结、大总结、导入、重建不再分别保存多个 Profile 标准。
- 自动开关只有：自动审核、自动提取、自动小总结。
- 大总结没有自动开关。

## 6. 请求与失败规则

- 正常请求只允许首轮 + 最多一次受控重试。
- 504/502/503、明确网络中断或空最终正文可以重试一次。
- 协议错误不由通用网络层“猜格式”或从 reasoning 中抢救。
- 提取、小总结、世界设定导入需要协议重试时，第二次是同一材料、同一协议的干净重开，不使用第二套 repair 模型阶段。
- 超过固定协议上限时整次拒绝部分提交，不静默截掉后半批。

## 7. 已删除的过度防御

当前运行链已删除：

- reasoning 最终协议抢救。
- `extractionRepair / summaryRepair` 第二模型阶段。
- 多格式 summary 恢复器。
- 正常 Extraction 的旧 ENTRY / 自然文本 parser。
- 重建的 JSON / 旧 ENTRY / 自然文本备用 parser。
- Entry Budget 自动删行、自动压缩历史和字符硬上限淘汰。
- 单条提取事实 180 字静默截断。
- 超过 32 个宿主时只提交前 32 个的部分成功逻辑。
- 分阶段 Profile、隐藏 `auditEnabled/extractionEnabled` 运行状态。
- 自动大总结及其失败批次队列。

## 8. 保留的必要防御

以下防御保护一致性或宿主边界，不重新解释剧情语义，因此保留：

- 世界书事务提交与失败回滚。
- 审核修正文在后续流水失败时的源正文恢复。
- 聊天/世界书/设置快照变化后的取消与重新验证。
- 世界书写入后的回读校验。
- Commit 前运行内存摘要新鲜度检查。
- UID / 完整稳定标题的精确身份匹配。
- 基石锁和焦点保护。
- API 网络/网关一次受控重试。
- 修正文完整性/截断检查，避免用半截正文覆盖原回复。

- 修复 MemoryRunner.apply 包装 Commit 结果时遗漏 businessChanges，SceneGroup 时间线现在读取真实提交变化。
