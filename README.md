# Mirror Abyss / 镜渊

版本：`4.0.21`

Mirror Abyss 是 SillyTavern 的长期游玩记忆扩展。世界书是唯一长期事实源；模型负责语义整理，插件只负责固定协议、精确身份、UID、单一事务入口、任务编排和界面。

## 单一链路

```text
UI或宿主事件 → TaskQueue → Controller → Memory/Import/Migration → ModelGateway + Protocol → WorldbookRepository → SillyTavern
```

- 提示词、协议校验、正文栏目和界面类型均读取 `src/core/schema.js`。
- 世界书读取、写入与回滚只经过 `WorldbookRepository`；只有带镜渊标记的世界书条目才归镜渊管理。
- 每次提交前后都从后端权威回读；SillyTavern 内存缓存不能单独构成写入成功。
- 条目身份严格使用“类型＋稳定名称”；不做相似度、包含关系或别名猜测。
- 模型不读取或输出 UID。
- 世界设定粘贴文本与 TXT 共用“AI整理 → 预览 → 确认写入”链。
- 世界设定、提取和总结均使用自然事实行协议，不使用额外对象外壳。
- 手记修改模式同时提供逐条“基石锁”和批量“设为/解除基石”；条目始终显示“可更新”或“基石只读”。

## 4.0.21 功能

- 只有经“世界设定导入”新建的条目由系统默认写在角色定义前；后续自动提取、总结和常规新增统一默认写在角色定义后。玩家可在手记管理态批量切换“定义前 / 后”，选择会随正文更新和插入校准持续保留。
- 六类条目在角色定义两侧共用唯一的粗到细顺序区间，因此玩家把任一类型移到定义前或定义后后，仍保持“基础设定→世界→场景→人物→物品→事件”。
- 手机端管理区改为四个高频入口加折叠的低频操作；类型筛选保持单行横向滑动，并增加全选、清空和独立的新建文件夹入口，减少首屏按钮堆叠。

## 4.0.20 功能

- 所有询问框改用浏览器原生 `dialog`，由浏览器负责居中、遮罩和手机视口适配，修复弹框跑到顶部及确认按钮无法操作。

## 4.0.19 功能

- 手记批量管理增加“移动到文件夹”，可将已选条目一次移入指定文件夹或默认分类；只更新 UID 文件夹布局，不改世界书事实。
- 新建与移动文件夹弹框增加内边距、字段间距和按钮间距，手机端按钮平分可用宽度。

## 4.0.18 功能

- 关联对象写入同一原生世界书正文的规范“镜渊关系”块；SillyTavern 开启递归且条目原生递归开关允许时，由宿主自己的递归扫描继续命中关联条目，不增加第二提示词或第二召回链。`无`、`none`、`null` 等空关联在协议边界统一归一为空数组。
- 大总结仅将非当前、非常驻的远端历史场景设为向量；把历史场景切换为原生常驻时同步关闭向量，禁止“常驻＋向量”。
- 手动小总结、手动大总结和手动合并把输出 UID 原子映射回原场景组，使其继续参与后续大总结；消息回滚只清理实际事务涉及的 UID，保留未受影响旧组。
- 大总结按条目更新时间和 UID 稳定排列来源；整理输出继承来源中最新的消息锚点，手动点击不会把远期条目误排成近期事实。
- 部署 ZIP 内固定为唯一 `mirror-abyss/` 根目录；所有归档目录为 `0755`、普通文件为 `0644`，打包后会校验顶层结构和 Unix 权限元数据。

## 4.0.17 功能

- 保持现有排版、分页、按钮与单滚动结构不变，仅将面板材质改为白色半透明玻璃，并为外框、页签分隔、启动徽记与运行状态加入非对称“镜渊遗迹终端”视觉层；装饰层不接收点击，也不参与布局尺寸。
- 增加低成本边框光流、徽记呼吸与运行状态脉冲；系统启用“减少动态效果”时会全部停用动画并保留静态边框。
- 异步审核、提取、总结、导入及世界书刷新在提交运行状态前校验原聊天与原世界书；取消或切换聊天后的迟到结果直接丢弃，不会写进新聊天或残留可重试失败。
- 运行页没有整理失败记录时不再把空值渲染成字面量 `null`。

## 4.0.16 功能

- 提取只接受正文叙事层中本轮新发生且已经成立的增量事实；旧事实核对、世界书诊断、冲突说明、建议、修正方案和待玩家确认内容不再写入。
- 已有对象必须复用相关条目的原生类型与稳定名称，避免为了覆盖类型而把同一对象重复建成错类型条目。

## 4.0.15 功能

- 同一类型的条目使用最后一次事实活动轮次生成原生 `order`：预算评估优先保留近期事实，ST 最终组装仍按远期→近期排列；六类继续固定为“基础设定→世界 / 场景→人物→物品→事件”，数值始终位于 ST 原生 0–9999 范围。

- 修复生成新 Swipe 时先回滚后又提取旧候选的问题：尚未完成的 overswipe 只回滚旧事务，新正文仍只由 `MESSAGE_RECEIVED` 单链处理；切换已有候选继续即时重处理。

- 修正提取、导入和总结共用的栏目规则提示：栏目名现在明确为当前 Schema 的封闭枚举，必须逐字复制；移除会诱导模型输出不存在“外观”栏目的错误示例，不放宽严格解析器。

- 次关键词保存要求完整的原生载荷，移除对旧原始字段的兼容回退；无效 `selectiveLogic` 会指出 UID 和原生字段，不再静默显示成另一种语义。

- 主、次关键词输入保留 SillyTavern 正则表达式内的逗号（如 `/a{1,3}/u`），并显式提示旧条目 `selective=false` 时次关键词尚未生效。

- 玩家审核提示词改为输入时立即进入原有设置保存链，避免切换运行/手记/维护页面时浏览器尚未提交 `change` 而丢失本次规则。

- 提取提示词明确区分当前AI正文、玩家意图与旧世界书上下文，并要求对已发生且有结果/影响的一次性行动保留事件事实，减少旧状态被误写为本轮变化或事件被其他类型吞并。

- 召回设置完整映射 SillyTavern 原生主要关键词 `key`、次关键词 `keysecondary` 与四种 `selectiveLogic`；保存时维持宿主要求的 `selective=true`，编辑、世界书写入、权威回读和基石只读均复用同一现有链路。

- TXT 导入改用显式可见的 44px 文件选择按钮，避免被 SillyTavern 的全局文件输入样式隐藏；仍与纯文本共用唯一 AI 预览与世界书写入链。

- 手机端筛选、批量管理、文件夹、条目工具与召回设置统一改为换行布局，消除第二条横向滚动，并将筛选触控高度固定为 44px。

- 用插件内唯一 DOM 模态层替换浏览器原生 `prompt/confirm`，确保文件夹、校准、合并、删除和重置操作可在 SillyTavern 内嵌浏览器中实际执行。

- 明确区分模型协议中的“类型”与“栏目”，避免把模板说明“人物：身份”误写进类型字段。
- 入口使用与清单版本一致的 `app.js` 缓存键，构建产物同时写入同一版本标记。
- 构建、校验和打包忽略 macOS AppleDouble 元数据，外置卷上不再把 `._*.js` 当作源码。

- 可选择 SillyTavern 连接配置并执行真实 API 测试；不会切换宿主全局连接。
- 单执行队列统一自动处理、人工处理、总结、回滚与写入；可以取消当前及全部等待任务。
- 聊天消息显示审核、修正、提取和写入状态；自动总结失败保留精确来源并可逐项重试。
- AI 正文 Edit/Swipe 先按 UID 回滚再处理新正文；用户消息 Edit 与 Delete 只回滚受影响写入。
- 世界书原生常驻、主要关键词与两项递归开关可查看和编辑；内容更新不会覆盖玩家设置。
- 向量召回只用于大总结后的远端历史场景；人物、物品、事件、世界与基础设定不会因大总结被误转为向量。
- 原生插入只写 `position/order`：世界设定导入的新条目默认位于角色定义前，之后产生的新条目默认位于角色定义后；玩家可逐批切换，任一侧均按六类粗到细排列。SillyTavern继续独占主提示词、角色卡、示例、AN、聊天历史、实际Token预算与最终组装。
- “校准ST插入”只修正可写条目的原生位置与顺序，不重置关键词、常驻、递归或向量状态；旧基石若偏离规划会明确报告并要求先解锁。
- 人物支持唯一主焦点；焦点只调整原生召回并防止删除或被总结改换身份，`【条目】`直接关联可跳转。
- 手记支持单项折叠展开、文件夹折叠与排序、同名精确合并、安全删除、条目排序和文件夹内独立分页。
- 面板固定外壳，异步数据先离屏完成再原子显示；任务状态局部更新，不清空操作页面。
- 插件内部保存产生的宿主更新事件会延迟到队列提交边界统一同步，避免同一次操作连续重建页面。
- 手记展开项直接提供主焦点、关键词触发、常驻与递归设置；基石项保留同样的只读状态视图。
- 管理选择复用类型图标槽位，手机端批量与文件夹操作采用紧凑工具栏，任务反馈不再替换按钮文字。
- 自动创建的聊天世界书会同步打开宿主编辑器；普通写入不抢占其他编辑器，并可从运行页定位本次更新。
- 世界设定文本与 TXT 共用 AI 预览链并统一写为基石只读；手动条目使用同一基石锁。
- 支持游戏时间锚点、世界书健康概览、严格 JSON 兼容、提取传输副本敏感词替换。
- 旧格式迁移严格限定为当前标题和正文模板，先扫描预览、确认写入、保留 UID，并可撤销。
- 维护页提供三轮真实验收、诊断 JSON 导出、玩家完整审核提示词与完整重置。
- 审核的语义标准完全由玩家提示词定义；插件只维护可解析的返回协议，不叠加隐藏审核规则。
- 总结来源标识与协议统一为裸 `条目N`，错误会同时显示无效编号和当前批次合法集合。

## GitHub 安装

将源码包内 `Mirror-Abyss-4.0.21/` 的内容放在 GitHub 仓库根目录；`manifest.json`、`index.js`、`app.js` 与 `style.css` 必须位于根目录，不能只上传 ZIP。然后在 SillyTavern 的“扩展 → 安装扩展”中粘贴该仓库地址。

`index.js` 是静态生命周期入口，加载构建产物 `app.js`；`style.css` 由宿主按清单加载。运行时不会请求 `src/`。请使用当前 SillyTavern release；项目没有虚构未经实机验证的最低客户端版本。

## 本地部署包安装

部署包只包含宿主运行所需文件，归档内固定为唯一顶层目录 `mirror-abyss/`。将部署包直接解压到 SillyTavern 的 `public/scripts/extensions/third-party/`，最终必须形成：

```text
public/scripts/extensions/third-party/mirror-abyss/manifest.json
```

升级时覆盖同一个 `mirror-abyss/` 目录。若曾解压过以版本号命名的目录（例如 `Mirror-Abyss-4.0.17/`），请在保留必要备份后移走旧目录，确认 `third-party/` 下只剩一个镜渊插件副本，再重启 SillyTavern 并强制刷新页面；否则宿主可能同时加载两份插件。不要把 ZIP 文件本身放入插件目录，也不要形成 `mirror-abyss/mirror-abyss/` 双层嵌套。

SillyTavern 同一用户、同一聊天与同一世界书的验收和正常使用应保持单个 ST 页面；宿主的多个页面同时编辑同一世界书可能发生 last-write 覆盖，这属于宿主多窗口写入边界，不是 Mirror Abyss 的第二写入链或内部状态缺陷。

部署归档中的目录权限统一为 `0755`、文件权限统一为 `0644`，可以由不同于打包者的普通系统用户读取。源码包仍使用带版本号的顶层目录，用于 GitHub 发布和继续开发。

## 验证

```bash
npm run build
npm run verify
npm run package
```

打包器还会校验发布目录、两个 ZIP 文件和 `SHA256SUMS.txt` 本身分别为 `0755` 与 `0644`。若源码位于 exFAT、SMB `noowners` 等不能保存 POSIX 权限的卷，默认 `release/` 会明确失败，不能把合成的 `0700` 误报为已修复；请把候选输出到支持 POSIX 权限的目录，例如：

```bash
npm run package -- --output /path/on/posix-filesystem/mirror-abyss-release
```

最终交付 SHA-256 必须从完成实机验收后、源码冻结时的这一轮产物重算；候选打包哈希不能提前写进最终报告。

不要直接编辑根目录 `app.js`；它由 `src/` 生成。架构边界和修改路由见 `ARCHITECTURE.md`，错误定性见 `ERROR-CATALOG.md`。维护页的“三轮完整验收”会调用当前模型路由并执行可回滚的临时世界书事务，因此会产生少量模型请求。
