# Mirror Abyss / 镜渊 3.0.0-lite.ui.10-final-candidate-v2

世界书是唯一长期事实源。模型负责语义整理，插件只负责批次、UID、保存、回读与回滚。

## 当前版本来源

- 本版本以 ui.9.1 运行修复包为直接基线。
- 它是独立的新版本，不声明为 GitHub `616a8d85` 的构建产物。
- 本轮保持唯一提取/审核/总结协议，收紧模型输出兼容边界，并移除运行时事实缓存和插件端事实推断。

## 本轮逻辑清理

- 删除回滚链中只写不读的局部状态，以及没有任何调用入口的旧回合快照删除方法。
- 回滚期间收到的 `GENERATION_ENDED` 只暂存消息索引；UID 回滚完成并解除独占区后再进入同一任务队列。
- 插件停用或切换聊天会提升仍在运行的来源回滚作用域版本，使旧回滚快照在下一校验点确定失效；活动 worker 的 barrier 保留到其 `finally` 真正退出。
- 手动总结、合并等 maintenance 任务产生的无剧情回合临时提交回执，只保留到该任务成功完成；成功后清理本次新增的无回合回执，避免聊天元数据长期累积。
- 26 个内部模块均可从运行入口到达，没有删除模块级代码。

## 地点边界稳定性

- SceneGroup 换场仍只认主预设明确的 `地点：` 字段；没有该字段时继续沿用当前 SceneGroup。
- 两个明确地点标签先做原有机械归一化，再用保守字符串相似度判断标签是否只是同一地点的详细/简写变化；阈值固定为 `0.77`。
- 高相似时保留原 SceneGroup 稳定名，不关闭旧组、不触发因换场产生的小总结。
- 两边存在不同地点编号时仍直接视为不同地点，例如 `B4-01` 与 `B4-02`。
- 该相似度只服务 SceneGroup 地点边界，不用于人物、事件、物品或世界书条目匹配；条目匹配规则保持不变。

## SillyTavern 源事件取消语义

- `MESSAGE_EDITED / MESSAGE_SWIPED / MESSAGE_DELETED` 仍然会使对应旧正文快照失效，并触发近期 UID 回滚；这属于正常来源变更，不是插件错误。
- 因来源变更被取消的运行任务和排队任务统一标记为 `MA_TASK_CANCELLED`，自动流程不再把它记录成失败。
- 回滚独占区存续期间，状态栏由来源回滚流程持有，不再被旧任务的“任务已取消”状态覆盖。
- `MESSAGE_DELETED` 只按 SillyTavern 提供的删除索引回滚该位置及之后受影响的近期回合，不把整个聊天视为损坏。


## 提取链路清理（ui.6）

- 正式提取只有一条入口：`runTask('extraction') → MemoryRunner.extract()`；删除 `diagnosticExtraction → runExtractionOnly → deterministicOnly` 验收旁路。
- 自动验收不再使用独立提取写入路径，直接调用正式 `extraction` 链。
- `extractionPrompts` 只生成一份正式提示词；删除 extraction 专用 `compact` / `retryReason` 提示词变体。
- 删除已无 UI 入口却仍会从旧设置加载的 `extractionPrompt` 隐藏配置；旧版本残留提取提示词不再能作为“附加要求”进入模型。
- 协议失败后的第二次请求只原样重放同一份提取 Prompt，不再切换 compact Prompt、不再回灌失败原因、不再单独关闭 preset。
- 删除未被消费的 `promptOptions.requestTime`、`extractionWorldbookIndex(..., compact)` 参数、`canonicalExtractionType` 死导出/死函数及测试专用导出。
- 固定事实解析器只保留唯一 `事实｜类型｜稳定名称｜栏目｜建立/变化/结束｜关联对象｜完整事实` 入口；删除无实际第二协议的回退判断。
- 模型请求公共层不再重复注入一份 extraction 协议正文；协议文本只由 `protocols → extractionPrompts` 提供一次。
- ui.6 当时未增加 JSON/括号兼容；当前版本的兼容层见下方“最终候选收束”。

## 提取重试边界清理（ui.7）

- 延续 ui.6 的唯一正式提取链，不增加 Prompt、解析器、写入入口或兼容旁路。
- 只有模型请求成功、但最终文本未形成固定事实协议时，才原样重放同一请求一次。
- 请求失败、鉴权/参数错误、任务取消和解析器自身异常立即沿原错误边界上抛，不再误作协议失败额外调用模型。
- 可重复行为基准覆盖：首轮成功、明确“无”、协议失败后成功、连续协议失败、非重试请求错误、任务取消。
- 基准同时校验协议重放的 Prompt 与响应预算指纹完全一致。

## 模块技术债清理（ui.8）

- 模块边界统一按“输入 → 单一处理 → 输出”检查；26 个内部模块全部可从发布入口到达并可独立加载。
- 自动正文链只监听当前宿主的 `GENERATION_ENDED`：删除 `MESSAGE_RECEIVED` 兼容入口、650/220ms 稳定检测和诊断模块的 50ms 轮询。
- SceneGroup 时间线格式只由 `util.normalizeEventTimeline` 规范化；宿主与内存模块不再各自维护一套实现。
- 删除旧审核默认提示词迁移、旧事件栏目清理、旧 SceneGroup 格式推断、旧运行时投影清理及 `commitReceipts → turnRollbackSnapshots` 转换。
- 删除生产包测试导出、重复的 `migrateWorldbook` 全局别名，以及函数级调用图中没有当前消费者的节点。
- 未分类条目使用当前 `unclassified-object` 角色，不再携带 `legacy-object` 历史语义。
- ui.8 只接受当前数据协议；来自更早版本的设置、时间线和回滚元数据不会自动转换。需要保留旧状态时，应先用 ui.7 完成过渡。

## 工程质量收束（ui.9）+ 运行修复（ui.9.1）

- 场景阶段只由 `governance.resolveSceneStages` 计算；召回策略与活动上下文共用同一结果，不再各自排序。
- 基础设定只由 `semantic.isFoundationEntry` 判断；召回策略不再保留第二份同义实现。
- SceneGroup 只使用 `groupUid` 作为身份，时间线规范化只保留 `util.normalizeEventTimeline` 一个实现。
- 玩家焦点只持久化在世界书条目扩展的 `focus` 字段；删除聊天元数据中的 `focusUid / focusTitle` 双写与补偿链。
- 世界书提交、回滚、召回投影不再传递始终为空的焦点参数；模块接口只保留实际消费的数据。
- 删除无消费者的兼容别名、匹配辅助函数及其级联死代码；停止以减少行数为目标，转入稳定性验收。
- `engineering-chain-benchmark.mjs` 覆盖提取输入、确定性计划、投影输出、场景/焦点权威、审核、修正、世界设定、设置边界和错误定位。

## 运行修复（ui.9.1）

- 恢复 `MESSAGE_RECEIVED + GENERATION_ENDED` 的自动触发兼容入口，并恢复 650/220ms 正文稳定检测，避免部分宿主环境只靠 `GENERATION_ENDED` 导致自动链不触发或触发过早。
- 恢复 `pendingMessageTimers` 清理链，在插件停用、聊天切换、验收模式切换、重置与任务取消时同步清空未决正文定时器。
- 固定事实解析新增“整行外层括号/引号包裹”机械去壳，接受如 `（事实｜人物｜...）`、`【事实｜人物｜...】` 这类仅多一层包裹的返回，不改变唯一字段协议。

## 最终候选收束（ui.10）

- 世界书仍是唯一长期事实源；删除解析条目的运行时事实缓存，所有业务读取重新打开并读取当前绑定的权威世界书。
- 删除插件根据名称或关键词自行补写“临时 / 身份未明”的逻辑；插件不再替模型推断事实标签。
- 唯一固定事实协议保持不变。兼容层只机械接受 JSON 对象/数组、Markdown JSON 外壳和说明文字中的第一个完整 JSON 值，再映射为同一固定协议。
- JSON 兼容不补字段：类型、稳定名称、栏目、变化、关联对象、完整事实任一键缺失即拒绝；变化必须明确为“建立 / 变化 / 结束”。
- 提取模型请求前增加固定词表的成人/肉体敏感词薄清洗；只修改发送给提取模型的传输副本，原聊天正文和世界书均不修改，不使用上下文猜测。
- `MESSAGE_RECEIVED + GENERATION_ENDED` 保持兼容；同一正文的后发完成事件替换前一稳定检测定时器，行为基准确认只进入一次正式任务队列。
- `dead-code-audit.mjs` 修复模板字符串表达式引用的假阳性；新增 `runtime-chain-benchmark.mjs`，并扩充提取格式与清洗测试。
- 主面板沿用“运行 / 手记 / 设置 / 维护”命名；“手记”页仍直接管理唯一事实源世界书，不建立独立数据层。
- “手记”的映射参数明确显示条目 UID；UID 仍只用于插件身份管理，不进入模型 Prompt。
- 21 项历史用户决定已逐项完成代码证据闭环；其中自由栏目要求已被后续严格合法栏目协议取代，未重新放宽解析器。

## 当前主链

```text
当前 AI 正文 + 玩家本轮回复 + 上一轮完整世界书
→ 提取细颗粒事实
→ 世界书

同一批世界书条目
→ 小总结：细 → 中
→ 返回什么就更新什么；本批未返回的旧条目删除

已完成小总结的条目
→ 大总结：中 → 粗
→ 同一完整条目整理协议
```

## 总结与人工整理

- UID 永远只在插件内部，模型看不到 UID。
- 模型只看到本次请求的临时 `条目1 / 条目2 / ...` 与完整正文。
- 原条目仍存在：返回原临时编号，系统保持原 UID 并整条更新。
- 真正形成新条目：模型返回 `新条目N`，系统创建新 UID。
- 本批原条目未被模型返回：系统删除其旧 UID。
- 小总结、大总结、选中总结、人工合并共用同一套完整条目整理方式。
- 总结协议没有空结果分支，也没有写回/移除/沉降、逐栏目 patch 或标题身份匹配。
- 人工合并与人工删除遇到基石锁时，先解除锁定再执行。

## 整本世界书整理

整本当前世界书一次交给模型，按大总结的长期颗粒度标准整理。先生成预览，确认后提交；失败保留旧书，提交后可撤销一次。

不再使用规划、分批、覆盖率、场景锚点、地区轮、规则轮等旧重建流程。

## 其他已收缩规则

- 审核只看当前 AI 正文。
- 正文修正只生成一次完整替换正文，不检查是否截断。
- 游戏时间不再保存独立聊天状态；设置后写成常驻 `基础设定｜游戏时间` 世界书条目，并随上一轮世界书一起进入提取。
- 不再执行离开场景时的额外世界书清理。
- 不再执行物品持有者/位置到人物或场景的隐藏同步。
- 玩家直接编辑世界书时不做额外语义治理，原 UID 保持不变。
- 重置只有“重置插件和世界书”：恢复默认设置、清除当前聊天镜渊状态并清空当前绑定世界书。
- 审核提示词按当前设置原样读取，不再识别或替换任何历史默认提示词。

## 保存保护

世界书仍使用正式保存、保存后权威回读和失败回滚。玩家在世界书中的直接修改不会因为旧 digest 被镜渊拒绝。

## 回合 UID 回滚

- 不保存整本世界书历史快照。
- 每个真实剧情回合只保存“该回合实际改动过的 UID → 本回合第一次修改前的完整条目”。
- 同一回合内提取、小总结、大总结反复修改同一 UID，只保留最早前态。
- 只保留最近 20 个剧情回合；手动维护任务不占用剧情回合快照。
- Edit / Swipe / Delete 触发后，当前聊天的镜渊运行任务与排队任务全部取消并清空，同时冻结新的镜渊任务；不再保留其他后台任务继续写世界书。
- 已经取得执行权的旧任务只等待其现有 Promise 确定性收尾，不再使用固定轮询或最长 4 秒猜测等待。
- 回滚本身不进入普通任务/维护队列；它在镜渊内部具有独占写入边界。
- 同一聊天连续出现多个 Edit / Swipe / Delete 时，只启动一个镜渊回滚 worker，后续边界串行合并处理，避免两个回滚互相覆盖。
- 回滚只恢复受影响 UID；其他 UID 不动。
- 回滚不检查玩家后来是否又编辑过该 UID，也不因后来锁定/焦点而拒绝恢复；回合前快照直接覆盖该 UID。
- 如果某 UID 是该回合新建的，撤回该回合时直接删除该 UID。
- 世界书写入已经成功、随后任务才被打断时，会立即使用本次 UID 前态反向恢复，避免留下半次写入。
- UID 恢复后的游标、内部提交回执和回合快照在一次聊天元数据提交中同步，避免同一次回滚拆成多次宿主保存。
- 回合回滚只读取当前 `turnRollbackSnapshots`；`commitReceipts` 继续承担当前提交回执职责，不再被解释成另一种数据结构。

## 回滚与 SillyTavern 宿主边界

- 镜渊只抢占自己的任务域，不抢占 SillyTavern。Edit / Swipe / Delete 的事件监听器保持同步返回，不等待完整回滚。
- 回滚调度使用 `0ms` 只退出当前宿主事件调用栈，不以固定毫秒数猜测 SillyTavern 的保存时机。
- 不取消、不阻塞 SillyTavern 自身的编辑、Swipe、生成或聊天保存。世界书与聊天元数据仍通过 SillyTavern 提供的正式保存接口提交。
- 世界书保存后继续执行 SillyTavern 的 World Info 列表同步与编辑器重载，避免后台状态和当前编辑器对象分裂。
- 游戏时间等会写世界书的镜渊入口统一进入任务队列；插件重置在回滚期间拒绝执行，避免旁路写入与 UID 恢复竞争。
