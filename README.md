# Mirror Abyss 4.0.118


## 4.0.118

- 以 SillyTavern release 实际宿主合同收口异步主链：自动处理只在 `MESSAGE_RECEIVED + CHARACTER_MESSAGE_RENDERED` 同一消息握手完成后进入队列，不再使用 `GENERATION_ENDED` 作为正文完成信号。
- 异步任务冻结当前 `chatId + message index + swipe_id + send_date + 正文指纹`；切聊、Edit、Swipe、Delete 会取消受影响任务，陈旧结果不得继续审核、提取或写入。
- `MESSAGE_DELETED` 不再把事件参数当消息 ID；改用删除前后消息身份快照机械定位删除起点与数量，再回滚并重排 receipt。
- Connection Profile 请求使用正式 CMRS `AbortSignal`，并恢复 Profile 的 preset/instruct；Chat Completion 与 Text Completion 均走宿主正式 Profile 合同。
- 世界书写入改为 `saveWorldInfo → 后端 no-cache fresh read → 提交指纹核验`；回读内容不等于预期提交时直接失败，不显示完成。
- 审核修正文写入后通过 ST `/api/chats/get` 或 `/api/chats/group/get` 做后端回读核验；`saveChatConditional()` 静默失败或超时时不得显示完成，也不得继续提取。
- 合并 4.0.116/4.0.117 已确认审核行为：最近完整对话只辅助指代；玩家审核要求位于实际用户请求；通过必须精确为 `[通过]`；不通过一次返回完整修正文并以 `[修正完毕]` 收口。
- 运行页保留自动修正，同时增加“查看当次审核原文”按钮；未知、未运行、跳过状态不会显示成“已通过”。


## 4.0.115

- 将“焦点必然常驻”固化为底层数据不变量：只要 `focus=true`，写入 SillyTavern 世界书的原生 `constant` 就必须为 `true`，关闭手动常驻也不会解除焦点常驻。
- 插件启动和切换聊天时会自动修复历史数据中 `focus=true` 但 `constant=false` 的异常条目；所有保存路径也会统一重新投影底层状态。
- 界面继续把“手动常驻”和“焦点强制常驻”分开显示，避免焦点人物的手动开关产生误导。


## 4.0.114

- 纯白皮肤中恢复关键状态的视觉层级：焦点常驻使用石墨实底，基石使用双线框，手动常驻使用虚线框。
- 焦点人物在列表与设置中明确标注为自动强制常驻；底层仍保持焦点唯一，并在切换焦点时同步更新世界书常驻状态。


## 4.0.113

- 仅更新皮肤与界面交互层：统一为纯白、浅灰与石墨黑的档案架视觉。
- 手机端保留搜索、类型筛选、批量选择、文件夹、总结、条目编辑和维护等完整功能，并补齐安全区与触控尺寸。
- 删除、整理、清空和重置改用插件内确认层；确定按钮固定在底部操作区，长内容和移动端均可正常操作。


## 4.0.112

- 审核要求模型从正文开头到结尾逐段列出全部问题；不通过结果必须以 `[审核完毕]` 收口，缺失时视为可能截断并停止修正。
- 第一次按“插件固定审核协议 → 玩家审核要求”拼接并生成完整问题清单；第二次只接收插件修正规则、问题清单、玩家本轮输入与原正文，严格逐项修复。
- 修正文必须以 `[修正完毕]` 收口；缺失时禁止覆盖当前正文，避免模型输出被截断后把完整消息替换成半篇。


## 4.0.111

- 小总结与大总结增加机械清理：当模型同时返回加工结果和原样来源时，原样来源不再因携带 `E` 引用而残留。
- 总结 Prompt 明确禁止把已被最终条目吸收的未加工来源原样保留。
- 大总结完成后同步刷新 SceneGroup 的最终 UID，避免继续引用已经删除的小总结条目。


## 4.0.110

- 修复“仅审核”在审核要求为空时零调用却显示普通完成：现在明确显示已跳过，并引导先填写审核要求。
- 运行轨道按真实执行阶段分别显示审核、修正、提取与写入；仅审核不再把未执行的提取和写入标成完成。
- 审核判定兼容模型常见的全角方括号、Markdown 粗体和代码围栏包装，仍严格要求首行是通过或不通过判定。


## 4.0.109

- 审核开关开启但审核要求为空时视为“无审核规则”：直接跳过审核；完整处理继续提取，纯审核操作直接结束。
- 只有真实发起并完成审核请求才记录 `audit/full`；空审核提示词不会伪记审核完成。
- 基石保护收回为代码自动写保护：自动提取、自动总结与模型整理继续不得修改基石条目。
- 玩家直接编辑条目正文、关键词、召回、注入位置、文件夹、焦点、基石状态与删除不再被基石保护拦截；UI 不再禁用这些控件。


## 4.0.108

- 修复审核任务被 `auditPrompt` 空值静默绕过：只要任务模式要求审核，就必须先实际执行审核。
- 审核要求为空时在审核入口直接失败，不再继续提取，也不再把未审核任务记录为 `full`。
- 审核通过仍静默保留正文；明确不通过才进入一次修正，再继续提取。


## 4.0.107

- 修复小总结／大总结六字段协议回退：运行 Prompt 补回实际六字段格式示范。
- 总结 Parser 对末尾事实仅缺一侧括号时执行与提取一致的机械收口，不增加语义判断。
- 总结结构确实无法确定时只允许一次格式纠错重试，并把第一次原始输出与具体结构错误交回模型；写入链、总结语义与世界书职责不变。


## 4.0.106

- 删除“先仅提取、后审核修正时回滚旧提取并重新提取”的兼容旁路。
- 正常回滚只恢复对应玩家行动之前的世界书／SceneGroup 状态，不调用模型，不触发重新审核或重新提取。
- 完整处理仍保持“审核 → 必要修正 → 提取一次”；仅提取是玩家明确绕过审核后的一次提取，完成后自动完整链不会再事后补审核。
- 其它审核、提取、场景切换、小总结、大总结、消息 Edit / Swipe / Delete 生命周期保持 4.0.105。


## 4.0.105

- 审核与修正重新分离：审核固定只返回 `[通过]` 或 `[不通过] + 问题`；只有明确不通过才发起第二次修正请求，审核协议错误绝不替换正文。
- 审核输入加入本轮玩家输入，使角色边界审核能够识别玩家已明确给出的意图、方向、要求与授权。
- 场景切换顺序改为：先完成本轮提取并解析出新场景，但暂不写入；立即用“本轮写入前”的旧 SceneGroup 小总结；达到水位立即大总结；随后 fresh read，再写入本轮新场景事实。
- 本轮提取事实不再污染刚结束场景的小总结输入；小总结与大总结产生的变化仍与触发它们的玩家回合一起记录，可统一回滚。
- 消息 Edit / Swipe / Delete 不再 `cancel++ + autoQueue=[]` 清空全部待处理正文；只移除受影响区间，排在前面的无关正文继续处理。
- 正在处理的受影响正文会立即失效；若取消发生在回执写入前，使用本回合进入提取前的世界书/SceneGroup 临时快照恢复；已完成回合继续用 receipt 前像一次恢复并重跑后续现存正文。
- 修复取消后 `busy` 可能永久不释放的问题；任务 finally 始终释放自身 busy。


## 4.0.104

- 审核 Prompt 拆分职责：玩家可编辑字段只保存“审核要求”；`[通过] / [不通过]` 返回协议由核心固定提供，不再依赖玩家填写。
- 固定审核协议要求：通过仅返回 `[通过]`；不通过首行返回 `[不通过]`，第二行起返回修正后的完整正文；不输出分析或附加说明，并保持正文原有结构与格式。
- 未修改模型调用、提取、总结、世界书写入、事件链与 Parser。

## 4.0.103

- 仅修改错误展示：失败时直接弹出原始 Error stack/message，不再混入 AI 原始文本。
- 核心、模型调用、Parser、提示词、事件、世界书写入和 UI 功能逻辑均保持 4.0.101。

低耦合短代码版。世界书是唯一长期剧情事实源；运行链保持“入口 → 读 → 处理 → 写 → fresh 回读 → 结束”。

## 4.0.103｜4.0.85 基线重落补丁

- 直接以 4.0.85 源码为基线重新落补丁；当前连接模型调用保持 `generateRaw({ systemPrompt, prompt, trimNames:false })`，Profile 调用保持原样。
- 审核：通过静默保留正文；不通过直接使用修正文替换正文并同步当前 swipe。
- 审核与提取回执区分阶段，审核完成不会再阻断同一消息的提取。
- 提取：世界书索引标记基石不可修改；加入五字段格式示范；末尾事实少一侧括号可机械收口；结构确实无法确定时只允许一次纠错重试。
- 小总结／大总结加入六字段格式示范；手动小总结／大总结恢复为手记页常显按钮。
- 删除没有产生实际世界书 changes 的消息时，只调整回执索引，不重新整理后续正文。
- 文件夹继续只使用条目 `folder` 字段；恢复 `+ 文件夹`／移动入口，并按 folder 渲染真实可折叠容器；基石条目允许移动文件夹。
- 去除条目入场动画，避免列表刷新时闪动。

## 4.0.85

- 修正 SillyTavern 1.18.0 实机世界书创建链：空闲名改读官方 `world_names`，不再拿 `/api/worldinfo/get` 的空对象判断文件存在。
- 正式保存后调用官方 `updateWorldInfoList()`，新世界书立即进入宿主世界书列表并绑定当前聊天。
- `GENERATION_ENDED` 按 ST 真实事件语义处理：事件值是 `chat.length`，因此统一回到最新 AI 消息，不再当作消息索引。
- 删除模型响应多层猜测、世界书 import 吞错、整本深比较、绑定补偿、手工原生条目 fallback 等防御性第二路径。
- 新条目只使用 SillyTavern 官方 `createWorldInfoEntry()`；保存只使用官方 `saveWorldInfo()`，随后 fresh read 当前世界书。
- SceneGroup 只保存实际写动 UID 与 open/closed/small/large 状态，不保存第二份剧情事实。
- 小总结读取最早 closed SceneGroup；大总结读取已小总结且尚未大总结的 SceneGroup；自动大总结使用同一总结函数。
- 整本世界书整理恢复为“一次模型整理 → 预览 → 玩家确认 → 保存”。
- 人工合并和明确删除可直接越过基石保护；自动提取/总结仍尊重基石。
- `世界｜游戏时间` 强制映射为 ST 原生常驻；managed 条目按类型与更新时间机械计算原生 `order`。
- 审核修正文同步当前 swipe。
- receipt 记录玩家输入索引；Edit/Swipe/Delete 会恢复受影响写入，pending Swipe 只回滚旧候选。
- 完整 Reset 会清空当前绑定世界书、聊天镜渊状态并恢复插件设置；“清空镜渊管理条目”仍作为独立轻量操作保留。
- 仅保留旧 `mirrorAbyssLite.currentGameTime` → `世界｜游戏时间` 的一次迁移。
- UI 重制为纯白视觉小说日志／调查手记风格：运行、手记、维护保持相同面板尺寸；运行页使用紧凑四阶段轨道和四个等尺寸操作按钮，手记页以世界事实阅读为主。
- 条目采用两段式交互：第一次“展开”只读正文，第二次“条目设置”会保留正文并在下方追加编辑与基础状态选项。
- 列表标签区分类型、真实关键词和已启用的常驻／焦点／基石状态；原始素材／小总结／大总结缩为阶段标记，文件夹作为路径，关键词数量与正文字数作为统计文字，注入位置只在设置层显示。
- 长关键词仅在卡片显示层省略，悬停可读完整原文；运行页空白区显示召回、写入、队列、连接方式与自动化开关等当前会话机械状态。
- 整理与导入收进次级工具区，并同时提供顶部标题与底部按钮两种收起入口。
- 增加镜面光环、微尘漂浮、页签扫光、标题呼吸线、卡片入场与处理中扫描等轻量动态，并兼容系统“减少动态效果”。
- 自动提取只发送完整紧凑索引（类型、稳定名称、关键词、已有栏目）与本轮玩家/AI 正文，不再发送旧条目正文。
- 自动提取结果向对应栏目末尾追加，未返回栏目原样保留；场景关闭后再由小总结压缩整理累计记录。
