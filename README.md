# Mirror Abyss / 镜渊 3.0.0-lite.ui.1-exact-match

世界书是唯一长期事实源。模型负责语义整理，插件只负责批次、UID、保存、回读与回滚。

## 当前主链

```text
当前 AI 正文 + 玩家本轮回复 + 上一轮完整世界书
→ 提取细颗粒事实
→ 世界书

同一批世界书条目
→ 小总结：细 → 中
→ 返回什么就更新什么；本批未返回的旧条目删除

已完成小总结的场景组集
→ 进入当前大组集（已有基础设定 + 本轮 S 小总结组集；基石锁仅保留为玩家手动治理记录）
→ 自动：达到阈值后立即执行大总结
→ 手动：不等待阈值，立即收拢当前大组集的全部小总结组执行大总结
→ S 场景组只作为材料并在成功后 S→L
→ 大总结正式产物只创建/更新“基础设定”
```

## 总结与人工整理

- UID 永远只在插件内部，模型看不到 UID。
- 模型只看到本次请求的临时 `条目1 / 条目2 / ...` 与完整正文。
- 原条目仍存在：返回原临时编号，系统保持原 UID 并整条更新。
- 真正形成新条目：模型返回 `新条目N`，系统创建新 UID。
- 本批原条目未被模型返回：系统删除其旧 UID。
- 小总结与人工合并继续使用完整条目整理协议；大总结使用独立的大组集协议。
- 大总结只读取已有基础设定与本轮若干个 S 小总结组；基石锁由玩家手动治理，不自动进入大总结提示词。
- 大总结正式输出只允许“基础设定”；不会用大总结正文改写或删除来源 S 场景条目。
- 总结协议没有逐栏目 patch 或标题身份匹配。
- 人工合并与人工删除遇到基石锁时，先解除锁定再执行。

## 整本世界书整理

整本当前世界书一次交给模型，按大总结的长期颗粒度标准整理。先生成预览，确认后提交；失败保留旧书，提交后可撤销一次。

不再使用规划、分批、覆盖率、场景锚点、地区轮、规则轮等旧重建流程。

## 其他已收缩规则

- 审核只看当前 AI 正文。
- 正文修正只生成一次完整替换正文，不检查是否截断。
- 游戏时间不再保存独立聊天状态；设置后写成常驻 `基础设定｜游戏时间` 世界书条目，并随上一轮世界书一起进入提取。
- 不再执行离开场景时的额外世界书清理。
- 不再执行物品持有者/位置到人物或场景的隐藏同步。
- 玩家直接编辑世界书时不做额外语义治理，原 UID 保持不变。
- 重置只有“重置插件和世界书”：恢复默认设置、清除当前聊天镜渊状态并清空当前绑定世界书。
- 历史提示词兼容只保留紧邻上一个部署版本，不再背负更早版本的默认提示词迁移。

## 保存保护

世界书仍使用正式保存、保存后权威回读和失败回滚。玩家在世界书中的直接修改不会因为旧 digest 被镜渊拒绝。

## 回合 UID 回滚

- 不保存整本世界书历史快照。
- 每个真实剧情回合保存“该回合实际改动过的 UID → 本回合第一次修改前的完整条目”。
- 同一回合内提取、小总结、大总结反复修改同一 UID，只保留最早前态。
- 只保留最近 20 个剧情回合；手动维护任务不占用剧情回合快照。
- Edit / Swipe / Delete 一旦发生，当前聊天任务域直接取消并清空；不再判断哪些提取/小总结/大总结任务属于“受影响任务”。
- 回滚期间当前聊天不接受新的正文任务或维护任务；等旧请求真正退出后，任务系统保持空，直接读取 UID 回合快照恢复世界书。
- 根据 Edit / Swipe / Delete 对应的消息位置，找到该位置及其之后的回合 UID 记录，并按记录顺序倒序恢复完整条目原文。
- 如果某 UID 是被撤回回合中新建的，恢复时直接删除该 UID；已有 UID 则恢复快照中的完整原文。
- 恢复完成后删除已经失效的回合 UID 历史，再重新开放当前聊天任务并按现有对话重新排队。
- 回滚历史只认本版本启动之后真实生成的回合 UID 快照；旧 `commitReceipts` 不再折算成新回滚历史。

## 新运行基线

- 插件启动、并且当前聊天还没有新运行结构时，先读取当前绑定世界书实际存在的 UID。
- 当前 UID 只作为升级后的事实起点，不推断这些旧条目过去是否做过小总结或大总结。
- 启动基线只扫描当前世界书实际存在的 UID，不修改任何现有条目，也不推断历史小总结/大总结状态。
- 旧总结生命周期、旧场景状态和旧回滚历史直接废弃，不再做运行时兼容。
- 基线建立完成后才启动正文监听和任务；从此后的第一次有效写入开始重新记录 S/L、场景组、计数器和回合 UID 快照。
- 同一聊天后续再次启动看到新运行版本标记后直接继续，不会重复清除已经有效的新 S/L。

## UID 总结处理标记

- UID 本身保持稳定，不创建第二套“小总结 UID / 大总结 UID”。
- `S` 表示“这个 UID 的当前内容已经完成小总结”；`L` 表示“这个 UID 的当前内容已经完成大总结”。
- S/L 只保存在插件内部扩展字段，不进入模型输入，也不改变世界书条目的真实 UID。
- 正常提取再次创建或更新条目时，当前内容进入新剧情状态：新条目无标记，已存在条目的旧 S/L 标记被清除。
- 小总结实际写出的保留/新建条目标记为 S。
- 大总结成功后，本轮作为材料的 S 场景 UID 在同一次世界书事务中统一 S→L；大总结产生/更新的基础设定属于大总结层结果。
- 小总结只处理当前没有 S/L 的 UID；大总结只读取当前为 S 的场景材料；已经是 L 的当前状态不会重复进入大总结。
- 回滚恢复的是完整 UID 原文快照，因此 S/L 会自动恢复到目标回合当时的状态，不另建总结历史表。
## 当前场景组集

- 进入第一个有效场景时立即创建“当前场景组集”；它就是当前连续场景的条目文件夹。
- 每个正常剧情回合世界书提交并权威回读后，把本回合真实创建/更新后的完整条目直接写进当前组集；同一 UID 再次更新就替换组集里的同 UID 条目，真实删除则从组集移除。
- 地点不变时继续更新当前组集，不再额外生成每回合 stage 批次，也不再只保存一串 UID 等待以后重新找条目。
- 地点变化时关闭整个当前组集；小总结直接读取这个组集已经保存的完整条目，不再拿 UID 去当前世界书二次查找。
- 新地点立即创建新的场景组集；同一地点以后再次进入也创建新组集，不重新打开旧组集。
- 场景组只认 `memberEntries` 完整条目文件夹；旧 `memberUids / stages / summaryUids / settled / archive` 不再参与运行时读取或推断。

## 当前大组集与大总结

- 每个完成小总结的场景组集直接进入当前大组集；大组集的场景数量就是大总结计数器。
- 当前大组集保留当前基础设定、本轮已经完成小总结的 S 组集，以及玩家手动维护的基石锁记录；自动/立即大总结只读取基础设定与 S 小总结组。
- 基石锁只由玩家手动设置/解除；不会自动塞进大总结提示词。
- 已有非基石锁基础设定是大总结唯一允许用临时 `条目N` 直接保留、改写、合并或删除的旧条目。
- S 场景组集没有临时 `条目N` 身份，只是大总结的抽象材料；大总结不会把这些来源场景条目作为写回对象。
- 大总结正式产物只允许 `基础设定`。需要新增长期规律时创建新的基础设定 UID；已有基础设定可按原 UID 更新。
- 基础设定在这里专指“这个世界已经稳定形成的整体运行逻辑”；材料必须来自若干个已经完成的小总结，不把具体剧情直接扩大成世界规律。
- 大总结基础设定写入与本轮来源 UID 的 S→L 在同一次世界书事务中完成，因此回合 UID 快照能同时恢复正文与总结标记。
- 自动达到阈值或玩家点击“立即大总结”后，当前被收拢的小总结组退出；建立下一轮大组集，继续携带当前基础设定，并保留玩家手动维护的基石锁记录。
