# Mirror Abyss 2.0.0-lite.ui.15-rebuild.10

面向 SillyTavern 1.18 的轻量正文审核、事实提取、事件结算、总结沉降与世界书召回扩展。

本版继续以 **SillyTavern 聊天世界书作为唯一长期数据源**。没有第二剧情数据库、Runtime、持久 Outbox、事务模拟、Reconciler 或大型状态机。

## rebuild.10 调整

本次只更新世界书重建的全局收束逻辑，其他链路保持 `rebuild.9`。

- 重建不再按旧条目逐一翻写，而是先判断最终语义归属。
- 同类型且讲述同一件事的候选会合并为一个新条目。
- 模型可填写“保留方式：并入其他条目”，把附属物品、单次载体或重复说明并入规则、地区、事件或其他主体。
- 插件在全部请求结束后统一执行并入；目标条目尚未生成时也可以在后续轮出现。
- 事件重建不再写入【目标】与【未决】，只保留已经发生的参与、场景、关键进展和结果。
- 计划、下一步、尚未发生事项不会进入重建后的事件正文。
- 预览显示同义收束和附属并入数量；提交、回读、删除旧表与撤销机制保持不变。

## 本次更新范围

本包以 `2.0.0-lite.ui.15` 为代码基线，只更新以下链路：

- AI 辅助世界书重建；
- 角色信息来源边界；
- 同一事件生命周期聚合；
- 后台任务固定源正文快照。

世界书重建先生成预览，不直接修改旧表。提交时先写入并回读新结构，校验通过后才删除旧镜渊条目；失败时恢复旧表。用户手写且未受镜渊管理的条目不参与删除。

人物认知分为【已知】和【误信】。世界事实不自动等于角色已知；每条人物认知必须保留亲眼观察、听到对白、收到消息、查看记录、他人转述、亲身经历、可靠推理、特殊能力、公开信息、自身身份、自身行动或直接告知之一。

同一事件按目标、参与者、场景和未决因果持续更新。标题变化、动作推进和场景内移动不会单独建事件；目标与因果独立、能够单独结束的过程仍保持独立。

后台提取和总结固定读取被触发时的源正文。生成下一条正文只会把新任务放入同一聊天队列，不会取消正在运行的旧任务。

## 六类业务条目

模型只能输出：

- `人物`：身份、稳定能力、当前状态、该人物自身的关系、关键持有物、持续经历；
- `场景`：稳定空间知识、当前局部快照与关联入口；
- `物品`：关键物品的定义、功能、位置、持有者、状态和限制；
- `事件`：多对象过程、必要因果、阶段、未决事项和结果；
- `世界`：会随剧情变化、但影响范围超出单一人物或单一场景的区域、组织、权力、制度、资源网络和公开局势；
- `基础设定`：不随普通剧情变化的世界常识、自然规则、种族共性、能力技术、社会规则和地理框架。

不再创建独立的关系或地点条目；“全局 / 全局状态 / 世界局势”统一归入世界：

```text
关系事实 → 写入对应人物【关系】
地点知识 → 写入对应场景
全局状态与变化 → 写入世界条目
稳定世界框架 → 写入基础设定条目
```

基础设定是正式的第六类内容条目，并以常驻、递归隔离方式召回；长期焦点仍是任意条目的召回属性。

## 身份未明人物

正文没有明确说明陌生人、匿名账号、蒙面者或未知声音是谁时，插件不得把它猜成现有人物。只有该对象已经产生会持续影响后续的状态、关系、持有物、行动结果或未决联系时，才建立临时人物档。

临时档使用可观察称呼，并写入 `身份未明` 与 `临时` 管理关键词。相同对象后续继续更新该档；正文明确揭示真实身份后，临时档合并进已知人物主档并删除。两个无法可靠区分的陌生对象不会仅凭“都是陌生女人”而强行合并。

## 场景中心结构

场景负责组织局部世界，但不保存事件流水。

场景固定格式：

```text
【定义】
【空间结构】
【固定资源】
【持续变化】
【当前状态】
【在场】
【当前资源】
【活动关联】
【世界影响】
【局部约束】
【别名】
```

其中：

- `定义 / 空间结构 / 固定资源 / 持续变化`会随探索和事件结果持续补全；
- `当前状态 / 在场 / 当前资源 / 活动关联 / 世界影响 / 局部约束`是正文结束时的完整当前快照；
- 同一稳定地点持续更新同一场景条目；
- 单轮提取最多一个场景，并且必须是正文结束时实际所在的当前场景；
- 被提及但没有实际进入的地点不会被误标为当前场景。

场景知识可以越来越完整，但栏目按用途分层：当前快照允许最多信息，稳定结构只保留必要事实，持续变化与旧经历只保留一条过去时结果。动作流水、对话复述和过程链不会继续累积。详细规格见 `SCENE_POLICY.md`。

## 事件与直接分流

事件是唯一过程和结算容器。

已经成立且宿主明确的事实直接写入对应条目：

```text
人物受伤 → 人物【当前】
物品遗落 → 物品【当前】
场景出口坍塌 → 场景【持续变化】
王国开始公开通缉 → 世界【公开局势】或【世界变化】
```

事件只保留形成这些事实的必要因果和阶段节点，不复制对象条目的完整状态。事件结束后，小总结或大总结只分发仍然持续有效的影响；有历史价值的事件转为纯向量历史，无独立价值的事件容器可以退出。

换场景与事件结束互相独立：进入新场景不等于旧事件已经结束，同一场景内也可以先后结束和开始多个事件。

## 世界与基础设定

`世界`用于会变化的宏观状态：区域范围、跨场景地理关系、组织结构、控制权、现行制度、资源与交通网络、公开局势和持续影响。它不要求本轮已经实际跨越多个场景；只要正文明确说明该事实会作用于场景外对象或后续多个地点，就可以在普通提取阶段创建。

`基础设定`用于稳定框架：世界常识、自然规则、种族与生命、能力与技术、社会规则和地理框架。明确出现的新设定会在普通提取阶段主动创建，不再等待大总结。

世界【世界变化】仍压缩为一句过去时结果；【持续影响】最多保留四个明确对象或区域的持续结果。

## 场景中心召回

召回方式由代码根据条目角色和场景距离确定，模型不能输出常驻、关键词、向量、递归、深度或顺序。

| 条目 | 激活方式 | 可被递归带出 | 激活后继续关联 |
|---|---|---:|---:|
| 基础设定 | 常驻 | 否 | 否 |
| 长期焦点 | 常驻 | 否 | 否 |
| 当前场景 | 常驻 | 否 | 是 |
| 上一场景 | 关键词 | 否 | 是 |
| 远期场景 | 纯向量 | 否 | 是 |
| 活动事件 | 关键词 | 是 | 否 |
| 普通人物 | 关键词 | 是 | 否 |
| 关键物品 | 关键词 | 是 | 否 |
| 世界变化 | 关键词 | 是 | 是 |
| 关闭事件/历史总结 | 纯向量 | 否 | 否 |

场景迁移：

```text
最新场景 → 当前场景，常驻
次近场景 → 上一场景，关键词
更早场景 → 远期场景，纯向量
```

纯向量条目会清空真实关键词；当前场景、长期焦点和基础设定也不会同时保留关键词或向量。普通人物、物品和活动事件被场景带出后立即停止递归。只有场景与世界变化可以继续关联。

面板中的魔杖按钮可对既有镜渊管理条目执行“重新规划召回状态”。该操作不调用模型、不修改条目正文，只重算 SillyTavern 原生召回字段。

## 关键词控制

每条最多四个真实关键词，只保留：

- 稳定名称；
- 唯一别名；
- 明确专名或唯一称谓。

代码会删除类型词、泛词和描述性人物称呼，例如“人物、场景、事件、女孩、少女、房间、当前局势”等。`海蓝发少女`这类描述不会作为长期触发词。当前场景与纯向量条目的候选关键词只暂存在镜渊扩展字段中，方便以后恢复为上一场景关键词，不参与当前触发。

## 提取语法

```text
<<<ENTRY:类型:稳定名称>>>
<<<KEYWORDS>>>
- 稳定名称
- 唯一别名
<<<CONTENT>>>
【固定小标题】
- 精简事实
<<<END_ENTRY>>>
```

要求：

- 只记录正文已经成立且仍会影响后续的事实；
- 不写“供 AI 参考”、证据等级、推测、预测或剧情建议；
- 同一事实只有一个主要宿主；
- 每条事实尽量不超过 80 字；
- 每个小标题单轮最多 6 行；
- 单次最多 8 条，其中场景最多 1 条；
- 有效条目部分提交，异常片段单独隔离；
- 一个安全条目都无法恢复时，才额外调用一次格式修复模型。

## 审核后的正文替换

审核失败后，正文替换由 `HostAdapter.replaceAssistantText` 单点完成：

1. 校验聊天、消息索引、消息键和原正文哈希；
2. 同步 `message.mes` 与当前 swipe；
3. 清除可能遮挡正文的 `extra.display_text`；
4. 刷新消息并等待保存；
5. 回读正文、swipe 和显示缓存；
6. 任一校验失败即恢复原正文。

自动提取会等待替换完成，然后读取修正版正文。

## 504 控制

模型请求由独立轻量模块管理：

- 审核、修正、提取、格式修复和总结分别使用不同输出预算；
- 正常提取最多携带 5 个相关世界书条目，精简重试最多 3 个；
- 只有 502/503/504、HTML 网关页、`No message generated` 和明确网络错误使用精简提示词重试一次；
- 格式错误、聊天切换、用户取消和快照失效不会重试。

详见 `AUDIT_504.md`。

## 官方 Connection Profile

“镜渊处理 API”下拉框直接调用 SillyTavern 官方 Connection Profile 服务：

- 选择“当前 SillyTavern 连接”时继续走 `generateRaw()`；
- 选择某个 Profile 后，审核、修正、提取、小总结和大总结统一使用该 Profile；
- 不切换主聊天 API；
- 插件只保存 Profile ID，不保存 API Key、服务器地址、模型或预设正文。

## UI

入口是浏览器右侧中部的 44px 浮动圆形图标。召回区域显示：

- 当前、上一和远期场景；
- 焦点与基础设定；
- 世界变化；
- 常驻、真实关键词和纯向量；
- 关联入口、双向关联、关联终点和递归隔离；
- 角色定义前、角色定义后或对话深度；
- Order 与 Scan Depth。

UI 回读真实世界书字段，不使用“证据/存疑”层，也不自行决定调度。

## 分页面板与最终态回读

面板分为三个页面：

- `运行`：手动操作、队列与阶段状态；
- `召回`：世界书召回映射，每页 12 条；
- `设置`：Connection Profile、自动开关与总结阈值。

提取成功不会立即触发 UI 回读。插件会等待提取提交、自动总结和召回重排全部结束，再回读一次最终世界书，避免页面短暂显示旧数据或中间数据。

## 验证边界

本地测试覆盖语法、正文替换、504 精简重试、异步顺序、场景内容累积、六类提取、未知身份收敛、世界与基础设定主动建档、关键词清理、场景迁移、纯向量清键、递归限制、总结分发和召回 UI。

本地测试不能替代用户云端 SillyTavern、真实 Connection Profile、Vector Storage 配置和移动端主题。实机首次安装后，建议在面板点击一次“重新规划召回状态”，再观察三次连续换场景后的字段变化。


## ui.12 内容边界

- 浮动入口可拖动，位置只保存在浏览器本地。
- 物品条目只记录单个可追踪实例；同类集合保留在场景资源。
- 人物描写只保留少量影响识别、能力或剧情判断的客观特征。


## ui.13 小标题归一

二次提取前，插件会按条目类型统一同义小标题：

- 人物、物品：`【当前状态】`、`【状态】`统一为`【当前】`；
- 场景：`【当前】`、`【状态】`统一为`【当前状态】`；
- 事件：`【当前】`、`【当前状态】`统一为`【阶段】`；
- 世界：`【当前】`、`【当前状态】`统一为`【公开局势】`。

旧条目同时存在两个同义栏目时，同一状态槽保留正文中后出现的值。条目下一次被更新时，会自动保存为唯一规范小标题，不调用额外模型。

## ui.14 子条目分层、匹配收敛与分页

- 当前快照栏目拥有最高预算；身份、稳定、关系、持有等栏目使用较小预算；持续经历、持续变化、关键进展、结果、世界变化和持续影响只保留一条已发生结果。
- 人物称谓变体、已登记别名和正文明确揭示的伪装身份会命中原档。
- 同名重复档会选择主档、合并有效内容并删除副档。
- `位置/所在地/当前地点`统一为`当前位置`，`目标/当前目标/目的/计划`统一为`当前目标`。
- UI 只回读最终世界书；面板拆为三页，召回列表每页 12 条。


## ui.15 未知身份与主动全局建档

- 未揭示身份时建立独立临时人物档，不命中已知人物。
- 身份揭示后把临时档合并进已知人物主档并删除。
- 世界和基础设定都可以在普通提取阶段主动创建。
- 世界字段扩大到区域、组织、权力、制度、资源与交通和公开局势。


## 世界书重建请求调度

世界书重建属于一次性迁移，允许多次模型调用。插件将旧表拆成串行小批次，默认每批间隔 2.2 秒；遇到 429 会退避等待。每批成功后保存内存断点，失败后再次点击只继续未完成批次。普通游玩中的审核、提取和总结调用方式不受此机制影响。
